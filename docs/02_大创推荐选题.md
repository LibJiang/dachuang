# 大创推荐选题（基于田静老师研究方向）

> 依据：田静老师方向 = 后量子密码（PQC）、AI 同态安全、区块链、现代纠错码 → **面向这些计算密集型算法的高性能集成电路设计**。
> 本文件给出 6 个可选选题，按"难度 / 创新性 / 上手成本"排序，并给出立项书可直接套用的结构。
> 说明：选题面向本科生大创（1 年、3~4 人），优先考虑实验室已有平台（AMD PYNQ-Z2 / Xilinx FPGA / Vivado）。
> **若拿不到 PYNQ-Z2**，可把课题收敛为纯仿真 + 综合方向：T1/T2/T4/T6 都不依赖板卡；只有 T3/T5 强依赖上板。

## T1. 基于 FPGA 的 CRYSTALS-Kyber 模约减与 NTT 算术单元设计与优化

**一句话**：复现田老师组 APCCAS 2022 的 FLUT + K-RED 模约减，并在 FPGA 上做面积 / 关键路径优化。

**背景与意义**
- Kyber（ML-KEM）是 NIST 后量子标准，已被广泛部署。
- Kyber 的性能瓶颈在 NTT / CWM / INTT，而这些运算的公共基础是**模约减**（mod q，q=3329）。
- 硬件里除法又慢又贵，因此用移位、加减、查表代替除法是核心技巧。

**研究内容**
1. 用 Verilog 实现 13 位有符号数表示的模约减单元（加减后约减 + 乘法后约减）。
2. 实现 FLUT：`T_out = u[5:0]·59 + u[6]·3329`，其中 `59 = 2⁶−2²−1`，用移位减法代替乘法。
3. 实现 K-RED 段：`r = d1 − 13·d0`，其中 `13 = 2³+2²+1`。
4. 用 Python 穷举 / 随机验证 `r ≡ (N/2)⁻¹·c (mod 3329)`。
5. Vivado 综合，记录 LUT / FF / DSP / 关键路径 / 延迟，并与论文表 I 对比。

**技术路线**
```
算法建模(Python) → Verilog RTL → Testbench 仿真 → Vivado 综合 → PPA 对比 → 优化迭代
```

**预期成果**
- 可综合、可验证的模约减 / NTT 蝶形 RTL 模块
- 与论文可比甚至更优的 PPA 数据（LUT、FF、频率、延迟）
- 一份技术报告 + 复现代码 + 测试向量

**创新点（可写的增量）**
- 用更小的查找逻辑 / 流水线切分进一步缩短关键路径
- 支持多种参数（如不同 q 或不同位宽）的可配置约减
- 与 NTT 蝶形运算融合，减少寄存器与连线

**所需前置**：数电、Verilog 基础、模运算、Vivado 流程
**风险**：纯复现创新性偏弱 → 必须加一个明确的增量点

## T2. 面向后量子密码的可配置 NTT / 多项式乘法加速器

**一句话**：设计一个可配置的 NTT / INTT / 逐点相乘加速器，支持 Kyber，并可扩展到 Dilithium。

**背景与意义**
- 多项式乘法是格密码最耗时的运算，NTT 把 O(N²) 降到 O(N log N)。
- 不同 PQC 算法参数不同（N、q、旋转因子），可配置架构有通用价值。

**研究内容**
1. 实现基-2 / 基-4 NTT 蝶形单元与地址生成器。
2. 设计旋转因子存储（ROM / 分布式 RAM）与读写调度。
3. 实现 CWM（逐系数相乘）与 INTT 缩放。
4. 做成参数化 / 可配置模块，对比不同基与并行度的 PPA。
5. 与田老师组多项式乘法加速器论文做对比。

**技术路线**
```
参数化 RTL → 单蝶形验证 → 全 NTT 验证 → 综合 → 吞吐/面积对比 → 可配置扩展
```

**预期成果**
- 可配置 NTT / INTT / CWM RTL 与验证平台
- 吞吐率、面积、频率对比表
- 可扩展到 Kyber + Dilithium 的统一架构

**创新点**
- 统一支持多种参数 / 多种算法的可配置架构
- 存储与计算折叠、降低 BRAM 与连线开销
- 低延迟调度策略

**所需前置**：Verilog、FPGA、NTT 原理、模运算
**风险**：NTT 数学与调度较难，需要先吃透原理

## T3. Kyber 侧信道防护（掩码 + 洗牌）的 FPGA 实现与评估

**一句话**：在 FPGA 上实现带掩码 / 洗牌防护的 Kyber，并用 TVLA 评估抗侧信道能力。

**背景与意义**
- PQC 算法即使数学上安全，物理实现仍可能被功耗 / 电磁侧信道攻破。
- 田老师组有 Kyber 洗牌防护与两步攻击的工作（论文 4、5），方向完全对口。
- 这是"安全实现"方向，含金量高。

**研究内容**
1. 实现基础 Kyber 核心运算（或复用开源实现）。
2. 加入一阶布尔掩码 / 洗牌（shuffling）防护。
3. 搭建功耗采集平台（示波器 / 芯片功耗探针；条件不足可用仿真功耗模型）。
4. 用 TVLA（Test Vector Leakage Assessment）做泄漏评估。
5. 对比防护前后的面积、频率、吞吐与泄漏指标。

**技术路线**
```
基础 Kyber RTL → 加掩码/洗牌 → 功能验证 → 功耗采集 → TVLA 分析 → PPA-安全权衡
```

**预期成果**
- 带防护的 Kyber 硬件实现
- TVLA 评估报告与 PPA 对比
- 防护强度与开销的权衡分析

**创新点**
- 针对 Kyber 特定结构的低成本防护
- 洗牌 + 掩码组合策略
- 面向资源受限 FPGA 的轻量防护

**所需前置**：Verilog、FPGA、侧信道基础、统计检验
**风险**：功耗采集设备与实验条件要求较高；可先用仿真 / 功耗模型替代

## T4. 面向同态加密的矩阵-向量乘法 FPGA 加速器

**一句话**：为 FHE / 隐私推理中的矩阵-向量乘法设计低面积、高效率的 FPGA 加速器（对标 LEAM）。

**背景与意义**
- 同态加密允许在密文上直接计算，是"AI 同态安全"的核心。
- 矩阵-向量乘法（MVMult）是神经网络推理与 FHE 中的高频算子，计算量大。
- 田老师组有 LEAM（APCCAS 2024）与同态卷积（TVLSI 2022）工作。

**研究内容**
1. 分析 FHE 中 MVMult 的数据流与位宽特点。
2. 设计可复用的乘加阵列 / 脉动阵列。
3. 优化片上存储与数据复用，降低面积与带宽。
4. 在 FPGA 上实现并对比不同并行度。
5. 与 LEAM 等 SOTA 做 PPA 对比。

**技术路线**
```
算子分析 → 架构设计(脉动阵列/并行乘加) → RTL → 仿真 → 综合 → PPA 对比
```

**预期成果**
- MVMult FPGA 加速器 RTL 与验证平台
- 面积 / 吞吐 / 功耗对比
- 可扩展到卷积 / 同态神经网络

**创新点**
- 低面积可配置乘加阵列
- 数据复用与存储优化
- 面向 FHE 位宽特性的定制

**所需前置**：Verilog、FPGA、矩阵运算、同态加密直观理解
**风险**：FHE 数学门槛较高，建议只做算子层加速

## T5. 基于 PYNQ-Z2 的后量子安全通信边缘演示系统

**一句话**：在 PYNQ-Z2 上实现 Kyber / Dilithium 的软硬协同安全通信演示，体现"算法 + 硬件"完整链路。

**背景与意义**
- 后量子密码要落地到边缘设备，需要软硬协同与资源受限优化。
- PYNQ-Z2 兼具 ARM + FPGA，适合做"硬件加速 + 上位机演示"的完整系统。
- 演示效果好，答辩、竞赛都占优势。

**研究内容**
1. 在 PYNQ-Z2 上部署 Kyber / Dilithium（软件基线）。
2. 把最耗时的 NTT / 模约减下沉到 PL（FPGA）加速。
3. 设计 PS-PL 数据通路与 DMA。
4. 上位机（Python / Web）展示握手、加解密与性能对比。
5. 评估软硬协同的加速比与资源占用。

**技术路线**
```
软件基线 → 热点分析 → PL 加速模块 → PS-PL 集成 → 上位机演示 → 性能评估
```

**预期成果**
- 可运行的边缘安全通信 Demo（开源）
- 软硬协同加速比与资源数据
- 演示视频 + 文档 + 答辩材料

**创新点**
- 面向边缘设备的 PQC 软硬协同
- 完整可演示系统（不是单模块）
- 可与侧信道 / 轻量化结合

**所需前置**：Verilog、PYNQ / Vivado、Python、密码算法调用
**风险**：系统集成工作量大；建议先做单算法、单方向

## T6. 面向光通信 / 存储的 NB-LDPC 或 ORBGRAND 译码器硬件加速

**一句话**：设计高吞吐或低复杂度的纠错码译码器（NB-LDPC / ORBGRAND），对应田老师博士根基方向。

**背景与意义**
- 纠错码是通信、存储、PQC 容错的基础。
- NB-LDPC 与 GRAND 类译码是当前研究热点，硬件实现价值高。

**研究内容**
1. 选择 NB-LDPC（EMS / Min-Max）或 ORBGRAND 作为对象。
2. 设计译码算法到硬件的映射。
3. 优化存储、排序与并行度。
4. FPGA 实现并与文献对比吞吐 / 面积 / 功耗。
5. 分析误码率与硬件开销的权衡。

**技术路线**
```
算法仿真(BER) → 定点化 → 架构设计 → RTL → 仿真 → 综合 → 对比
```

**预期成果**
- 译码器 RTL 与 BER / PPA 评估
- 与 SOTA 的对比分析
- 可复现的测试平台

**创新点**
- 低复杂度排序 / 存储压缩
- 高吞吐并行架构
- LUT 辅助等轻量化技巧

**所需前置**：Verilog、FPGA、纠错码基础、概率统计
**风险**：纠错码理论门槛高，算法调试周期长

## 二、立项书可直接套用的结构

1. **项目名称**：从上面 6 个里选一个，尽量具体（含算法名 + 硬件平台 + 目标）。
2. **立项依据**：背景（量子威胁 / PQC 标准化 / 硬件瓶颈）+ 国内外现状 + 参考文献（直接用 `01_田静老师资料与研究方向.md` 的论文清单）。
3. **研究内容**：3~5 条，每条对应一个可交付模块。
4. **技术路线**：一张流程图 + 关键步骤说明。
5. **创新点**：2~3 条，强调"相比已有工作的增量"，不要只说"实现了"。
6. **进度安排**：按季度 / 月份拆分（建议见下）。
7. **预期成果**：RTL 代码、FPGA 验证、PPA 数据、技术报告、论文 / 专利 / 竞赛。
8. **团队分工**：算法、RTL、验证、系统集成。
9. **经费预算**：开发板、器件、测试设备、打印等。

### 建议进度（1 年）

| 阶段 | 时间 | 任务 |
|---|---|---|
| 调研 | 第 1–2 月 | 读 3~5 篇论文，搭环境，定指标 |
| 设计 | 第 3–4 月 | 算法建模、架构设计、模块划分 |
| 实现 | 第 5–7 月 | RTL 编码、Testbench、功能验证 |
| 优化 | 第 8–9 月 | 综合、时序、PPA 优化 |
| 评估 | 第 10–11 月 | 对比 SOTA、补实验、写报告 |
| 结题 | 第 12 月 | 答辩、开源、论文 / 专利 |

## 三、如何让选题"对上"田老师的方向

1. **算法选她做过的**：Kyber、McEliece、SIKE、HQC、Scloud+、同态卷积、NB-LDPC。
2. **切入点是硬件**：NTT、模约减、多项式乘法、矩阵-向量乘法、译码器、侧信道防护。
3. **指标用她的语言**：LUT / FF / DSP / BRAM、关键路径、频率、吞吐、延迟、PPA。
4. **引用她的论文**：立项书参考文献里放 3~5 篇她的工作，面试时能直接聊。
5. **先复现再改进**：复现论文 6（模约减）是最稳的第一步，再做增量。

## 四、避坑提醒

- 不要选"纯理论密码证明"类题目（与她的硬件组不匹配，且本科难出成果）。
- 不要一上来做完整 Kyber 芯片（周期不够），先做单个算术单元。
- 指标要可测量：每个模块都要有**面积 / 频率 / 延迟**数据。
- 早做版本管理：代码、测试向量、实验数据都进 Git（就是本仓库）。
- 注意开源协议与引用规范，复现代码要注明来源。
