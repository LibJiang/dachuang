# 板级 smoke 验收清单

> **这张表的性质**：检查项来自 `docs/18` §一的「允许清单」，逐条附依据；
> 判定标准为 `【本项目约定】`（仓库无此规定）。
> 目的：**只验证工具链 + 板子 + 下载线 + 串口通**，不验证 HQC 功能。
> 责任人：房煦然（验收）；执行：骆奕宾、曹子墨；平台：江力博。

---

## 一、范围（依据 `docs/18` §一原文）

**允许**：LED 闪烁、UART 收发、计数器、时钟/复位、JTAG 下载、AXI-Lite 寄存器读写 smoke。

**不允许**：SHAKE / 采样 / 乘法 / RS / RM / KEM Top 的"先写一版再说"。

> `docs/18` 原文另有：「不把"板级 LED/UART 通了"说成"HQC 跑通"」。

---

## 二、验收项（9 项，逐条附依据）

| # | 检查项 | 通过判据 | 依据 |
|:--:|:---|:---|:---|
| S1 | Vivado 工程可打开、可综合 | 综合无 error；有 utilization 报告 | `docs/18` §一 江力博任务「搭 Vivado 工程/约束/下载脚本」 |
| S2 | 约束文件生效 | 时钟约束已生效；频率与约束一致 | `docs/18` §一「约束骨架」；「不猜引脚、不写死电压」 |
| S3 | bit 生成并可下载 | 下载无 error，板上行为符合设计 | `docs/18` §五 证据要求「bit 下载截图/日志」 |
| S4 | 时钟与复位 | 复位后状态确定 | `docs/18` §一 允许清单「时钟/复位」 |
| S5 | LED | 按设计闪烁或按脚本点亮 | 允许清单「LED 闪烁」 |
| S6 | UART 收发 | PC 能收到板端打印；下发指令有回应 | 允许清单「UART 收发」+ §五 证据「UART 输出」 |
| S7 | 计数器 | 计数值按设计递增/回绕 | 允许清单「计数器」 |
| S8 | AXI-Lite 寄存器读写 | 写入后读回一致 | 允许清单「AXI-Lite 寄存器读写 smoke」 |
| S9 | JTAG 下载链路 | 能识别器件型号 | 允许清单「JTAG 下载」 |

> S2 只要求"时钟约束生效"，**不要求"零未约束路径"** —— smoke 阶段允许存在未约束的内部路径。
> 这一判据同样属于 `【本项目约定】`。

---

## 三、证据要求（依据 `docs/18` §五，缺一不可）

- Vivado 综合日志（含 utilization）
- bit 下载日志或截图
- UART 输出原始文本
- **接线说明**（哪根线接哪个口、跳线帽位置、供电方式）
- 板卡型号与序列号（若可读）

> 证据放 `data/logs/YYYY-MM-DD-board-smoke/`，并在 `report/llm_log/` 的纪录里链接。

## 五、判定 `【本项目约定】`

> 仓库未规定判定分级，以下为本项目约定，可按团队意见调整。

| 结论 | 条件 |
|:---|:---|
| **PASS** | S1–S9 全过，且证据齐全 |
| **PARTIAL** | 至少 S1/S3/S6 通过，其余有明确阻塞原因 |
| **FAIL** | S1 或 S3 未过（工具链或板子不通，其余无意义） |

**PARTIAL / FAIL 时必须写清**：卡在哪一项、已排查什么、下一步找谁。
