# 团队分工与国家级指标

> 目的：把“四人怎么分工、每周怎么集成、什么算国家级立项水平”写死，避免后期扯皮。
> 配套：`README.md` §6–§7、`plan.md`、`docs/08`、`docs/09`、`docs/contracts/`。

---

## 一、总原则

1. **先完整、后上板**：先让 HQC-128 完整 KEM 在 C/C++ + xsim + 综合里跑通；上板最后再定。
2. **接口先行**：模块 RTL 开始前，先冻结 `docs/contracts/` 对应契约。
3. **一次只动一个变量**：B 阶段只替换稀疏乘法；不要在换乘法的同时改采样/编码/字节序。
4. **证据说话**：每个结论必须有 `data/logs/` 或 `data/evidence/` 原始输出。
5. **原创性边界**：复现官方实现是基线；创新得分点必须能单独指出“哪一块是我的”。

---

## 二、四人分工

### A：算法与软件基线

**负责**

- HQC spec、参数集、KAT 来源与版本；
- 官方参考实现的获取、编译、运行；
- C/C++ 黄金模型（稀疏乘法、FHT、完整 KEM harness）；
- SHAKE256、固定重量采样、RS 编解码的软件基线；
- 系统级协同仿真的 C 侧调度与对拍。

**交付**

- `models/kem/`：官方参考 + `kat_check` + `roundtrip` + `bench`；
- `data/vectors/`、`data/golden/`：向量与期望输出；
- `data/logs/YYYY-MM-DD-hqc-baseline/`：KAT 原始日志；
- 协作纪录。

**验收**

- 官方 KAT 100/100 逐字节通过；
- 黄金模型与官方实现交叉验证；
- 给出 KeyGen / Encaps / Decaps 的软件基线耗时。

**接口**

- 给 B/C 提供：向量格式、字节序、稀疏位置表、期望输出；
- 给 D 提供：可复现的 KAT 命令与日志。

---

### B：稀疏乘法与存储架构

**负责**

- `sparse_qc_mult` RTL：循环移位、XOR 累加、模 \(X^n-1\) 折叠；
- `dense_qc_mult_baseline`：朴素基线，用于加速比；
- `LANES` 参数化、BRAM banking、位置表存储；
- 周期数、LUT/FF/BRAM、Fmax 的设计空间；
- 单元 testbench 与随机对拍；
- **兼任 Vivado 平台 owner**：xsim 回归、OOC 综合、PPA 报告归档（当前只有一台机器有 Vivado）。

**交付**

- `src/mult/`、`sim/tb_sparse_qc_mult.v`；
- `data/logs/.../xsim.log`；
- `data/evidence/.../utilization.rpt`、`timing_summary.rpt`；
- 1/2/4/8 路 Pareto 表。

**验收**

- 与 C 黄金逐 bit 一致（≥1000 组）；
- 稀疏 vs 朴素周期数 ≥10×；
- 4 路吞吐 ≥3×、资源 ≤2×；
- 契约冻结后接口不变；
- 每周五提供 xsim 回归日志 + 综合/时序报告。

**接口**

- 输入：A 的稠密向量、位置表、期望输出；
- 输出：C 需要的 `start/busy/done` 与 BRAM 读写接口。

---

### C：FHT 与 KEM 数据通路

**负责**

- `rm_fht128`：128 点 FHT、软/硬判决；
- `repetition_combine`：重复码合并；
- KEM 控制 FSM：KeyGen / Encaps / Decaps 的调度；
- AXI4-Lite / MMIO / BRAM 接口；
- 系统集成：把乘法、FHT、C 模型串起来。

**交付**

- `src/rm/`、`src/kem/`、`src/soc/`；
- `sim/tb_rm_fht128.v`、`sim/system/tb_hqc_kem.v`；
- 系统级协同仿真日志与端到端 KAT；
- 延迟分解表（乘法 / FHT / RS / SHAKE / 控制）。

**验收**

- FHT 与官方参考逐块一致（≥1000 组）；
- 端到端 KAT ≥10 组全过；
- 控制 FSM 无死锁，`busy/done` 语义符合契约；
- 延迟分解可解释。

**接口**

- 输入：A 的 KAT 与黄金、B 的乘法接口；
- 输出：D 需要的仿真入口与日志。

---

### D：验证、评测与文档

**负责**

- testbench 框架、随机向量生成、回归脚本；
- xsim 批处理、日志归档、`git diff --check`；
- 综合/实现/PPA 数据整理；
- 技术报告、答辩材料、协作纪录汇总；
- 查新与原创性差异表（SOCC 2023 / 公开 HQC 硬件）。

**交付**

- `sim/scripts/`、回归套件；
- `data/logs/`、`data/evidence/` 的 manifest；
- `report/` 报告与 `docs/records/`；
- “与组内 SOCC 2023 的差异表”。

**验收**

- 每次 PR 有验证命令与原始结果；
- 回归可一键复现；
- 报告中的每个数字都有证据路径；
- 差异表能回答“你的创新点是什么”。

## 三、接口与依赖

```text
A（算法/黄金/向量）
   │  向量、期望输出、KAT
   ▼
B（稀疏乘法） ──接口契约──► C（FHT/KEM/接口） ──► D（验证/评测/报告）
   ▲                                              │
   └──────────── 反馈问题 / 回归失败 ◄────────────┘
```

- **A → B/C**：向量格式、位序、位置表、字节序；
- **B → C**：`start/busy/done`、BRAM 读写、延迟；
- **C → D**：系统仿真入口、端到端 KAT；
- **D → 全员**：回归失败、PPA 数据、报告问题。

## 四、周节奏

| 时间 | 动作 | 产出 |
|:---|:---|:---|
| 周一 30 min | 对齐本周目标与接口 | 本周任务清单 |

### Vivado 平台 owner（当前由 B 兼任）

- 维护 `sim/run.ps1`、`sim/scripts/run_xsim.tcl`、`build/constraints/`；
- 每周五统一跑 xsim 回归 + OOC 综合，归档到 `data/logs/`、`data/evidence/`；

## 五、国家级立项指标（目标）

> **国家级和校级的分水岭**：不是“有没有板子”，而是**有没有完整的 KEM + KAT + 可复现证据 + 明确的创新增量 + 与基线的量化对比**。
> 只做一个乘法器，最多是校级工作量；做到“完整 KEM + 系统协同 + 设计空间 + 差异表”，才有国家级竞争力。
>
> 目标值，不是承诺；以仿真/综合实测为准。口径分开写：仿真 / 综合 / 上板。

**组内基线（SOCC 2023）**：

| 基线 | 器件 | LUT | FF | BRAM | Fmax | KeyGen / Encap / Decap |
|:---|:---|:---|:---|:---|:---|:---|
| SOCC 2023 | xc7a200t-3 | 19,794 | 11,079 | 68 | 178 MHz | 0.11 / 0.22 / 0.38 ms |

它已经做了**稀疏乘法、RM FHT、RS ePIBM、完整 HQC-128 KEM**。本项目不能把这四项本身当原创；
差异与增量见 `docs/11_组内基线与差异表.md`。

### 5.1 功能

| 指标 | 目标 |
|:---|:---|
| 完整 KEM | HQC-128 KeyGen / Encaps / Decaps + FO + 隐式拒绝 |
| 官方 KAT | 100/100 逐字节一致 |
| 单元随机 | 稀疏乘法、FHT 各 ≥1000 组 |
| 端到端协同仿真 | ≥10 组 KAT 全过 |
| 负向 | 篡改密文 → 隐式拒绝 |
| 错误数 | 0 mismatch |

### 5.2 性能/PPA

| 指标 | 目标 |
|:---|:---|
| 稀疏 vs 朴素乘法 | 周期数 ≥10× |
| 4 路并行 | 吞吐 ≥3×，资源 ≤2× |
| Decaps PL | ≤100k 周期（1 路）/ ≤30k（4 路） |
| Fmax | ≥100 MHz post-synthesis OOC；冲刺 125 MHz |
| PL 面积 | ≤35% LUT、≤30% BRAM、≤20% DSP（混合架构只算 PL） |
| 核心算子加速比 | ≥5× |
| 端到端加速比 | ≥2×（冲刺 3×，混合架构 vs 纯软件） |
| 系统集成 | V1 可选 RISC-V + PL 协处理器 |

> 不与论文的全硬件 KEM 直接比绝对延迟；论文在更大的 Artix-7 上、全硬件实现。
> 我们比的是资源受限平台、可编程性、设计空间和完整 KAT 证据链。

### 5.3 成果

- 可复现仓库 + 报告 + 答辩材料；
- 设计空间 Pareto 数据；
- 冲刺：论文 / 专利 / 竞赛（加分项，不是硬闸门）。

## 六、创新得分点（候选，需查新确认）

> **组内 SOCC 2023 已经做了**：稀疏乘法、RM FHT、RS ePIBM、完整 HQC-128 KEM。
> 这四项**不能**当本项目原创；下面是“论文没做/没强调”的候选增量。

| # | 候选得分点 | 为什么可能新 | 证明方式 |
|:---|:---|:---|:---|
| 1 | **RISC-V + HQC 协处理器** | 组内是固定硬件 KEM，不是可编程 SoC | MMIO/指令接口 + KAT + 软硬划分表 |
| 2 | **参数化稀疏乘法设计空间** | 组内是单一 128-bit/4-bank 配置 | 1/2/4/8 路、64/128-bit 的 Pareto |
| 3 | **混合软硬协同 + C/RTL 协同仿真** | 组内是全硬件；我们做资源受限平台混合方案 | 100 组 KAT + 10 组端到端 + 延迟分解 |
| 4 | **HQC-192/256 参数化** | 组内只实现 HQC-128 | 三参数集资源/延迟对比 |
| 5 | **恒定时间/故障检测**（选做） | 组内未涉及 | 侧信道/故障注入实验 |

**不能写**：“首次实现 HQC 硬件”“稀疏乘法是我们的创新”“完整 KEM 是我们的创新”。

**查新要求**：差异表见 `docs/11_组内基线与差异表.md`；没有差异表，不写“原创”。
如果组内已经做过某项，就换角度，不要硬碰。

## 七、风险与应对

| 风险 | 应对 |
|:---|:---|
| 四人节奏不一致 | 每周集成 + 接口契约冻结 |
| KAT 对不上 | 采样/编码/填充全用官方实现 |
| 稀疏乘法时序不收敛 | 先降频/加流水，再优化 |
| FHT 延迟超预算 | 全并行 → 半并行，按周期目标折中 |
| 上板条件不确定 | 上板设为最后可选项；仿真/综合先交付 |
| 原创性边界不清 | 先拿 SOCC 2023，写差异表；不把复现当原创 |
| 只有一台机器有 Vivado | B 兼任平台 owner，周五统一批处理；第二人装免费 Vivado BASIC 兜底 |
