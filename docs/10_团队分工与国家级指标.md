# 团队分工与国家级指标

> 目的：把“四人怎么分工、每周怎么集成、什么算国家级立项水平”写死，避免后期扯皮。
> 配套：`README.md` §6–§7、`plan.md`、`docs/08`、`docs/09`、`docs/contracts/`。

---

## 一、总原则

1. **先完整 RTL、后 FPGA 全功能跑通**：先让 HQC-128 完整 RTL KEM 通过官方 KAT；FPGA 是硬目标，ASIC 是条件阶段（不流片）。
2. **接口先行**：模块 RTL 开始前，先冻结 `docs/contracts/` 对应契约。
3. **一次只动一个模块**：不要在改乘法时同时改采样/编码/字节序；每次集成只引入一个变量。
4. **证据说话**：每个结论必须有 `data/logs/` 或 `data/evidence/` 原始输出。
5. **原创性边界**：复现官方实现是基线；创新得分点必须能单独指出“哪一块是我的”（ASIC/设计空间/开源）。

## 二、四人分工

### 骆弈宾：RTL-A 协议/SHAKE/控制

**负责**

- KEM/PKE 控制 FSM：KeyGen / Encaps / Decaps、FO、隐式拒绝、**常数时间比较**；
- **三阶段共享 SHAKE256 / Keccak**（KeyGen/Encaps/Decaps 复用）/ XOF / PRNG 的 RTL；
- 固定重量采样（w/w_r/w_e）的 RTL（常数时间）；
- 与官方 KAT 的协议级对拍；
- 与房煦然对接 KAT/向量，不维护 harness。

**交付**

- `src/kem/`、`src/sha3/`、`src/sampler/`；
- `sim/tb_sha3.v`、`sim/tb_sampler.v`、`sim/system/tb_hqc_kem.v`；
- KAT 对拍日志、共享/独立面积对比、恒定时间评估；
- 协作纪录。

**验收**

- SHAKE/采样与官方参考一致；三阶段共享无死锁；
- KEM 控制无死锁，`busy/done` 符合契约；
- 常数时间比较/采样通过审查与评估；
- 完整 RTL KAT 100/100。

**接口**

- 给曹子墨：控制/数据接口、字节序；
- 给房煦然：KAT 对拍需求、向量格式；
- 给江力博：系统集成所需的控制/数据接口。

---

### 曹子墨：RTL-B 算术/解码

**负责**

- **低延迟 dense×sparse 主方案**：循环移位、XOR 累加、模 \(X^n-1\) 折叠、流水线；
- `LANES` 参数化、BRAM banking、位置表存储、移位实现对比；
- Karatsuba/Toom-Cook 仅为老师举例，本项目不实现对照；
- RS 编码 + ePIBM 解码；
- RM 编码 + 128 点 FHT + 重复合并；
- 单元 testbench 与随机对拍。

**交付**

- `src/mult/`、`src/rs/`、`src/rm/`；
- `sim/tb_sparse_qc_mult*.v`、`sim/tb_rs_codec.v`、`sim/tb_rm_fht128.v`；
- 与官方向量对拍的日志；
- 1/2/4/8 路 Pareto 表。

**验收**

- 与 C 黄金逐 bit 一致（≥1000 组）；
- 低延迟 dense×sparse 周期/面积达成契约目标；
- 4 路吞吐 ≥3×、资源 ≤2×（按 Pareto 记录）；
- RS/RM 与官方测试向量一致；
- 契约冻结后接口不变。

**接口**

- 输入：骆弈宾的控制/向量、房煦然的 KAT/黄金；
- 输出：`start/busy/done`、BRAM 接口、PPA 数据。

### 江力博：项目负责人 / FPGA 与 IP 集成

**负责**

- 进度、周报、repo/CI；与房煦然共同维护总体计划；
- **Vivado 平台 owner + FPGA bring-up**：工程/约束/XDC、bit/hwh、板端下载、xsim 回归、OOC 综合、PPA；smoke RTL 由 RTL 线写，江只做工程/约束/下载/评审；
- 系统仿真框架：RTL 顶层 + KAT 向量 + 逐字节对拍；
- 板端 KAT 100/100、KeyGen/Encap/Decap 全功能跑通；
- **IP 工程化**：filelist/工程、寄存器映射、驱动示例、集成指南、release/changelog；
- ASIC 前端协调；ASIC 后端（P&R/STA）有余力再做；
- **不写 RTL 模块**，只做系统/验证/集成评审。

**交付**

- `sim/system/`、`sim/scripts/`、`board/`；
- `data/logs/`、`data/evidence/` 的板端/PPA 证据；
- **IP 交付包**（filelist、寄存器映射、驱动、集成指南、release）；
- 周报、系统仿真日志、FPGA/ASIC 报告。

**验收**

- 板端 KAT 100/100；KeyGen/Encap/Decap 全功能跑通；
- xsim smoke + 系统仿真；
- IP 交付包可被第三方按集成指南跑通；
- 每周五给出 xsim 回归 + 综合/PPA 报告；
- 不提交 RTL 模块（只 review）。

**接口**

- 给骆弈宾/曹子墨：系统集成入口、回归入口；
- 给房煦然：进度、证据、风险；
- 给老师：通过房煦然汇总技术状态。

## 三、接口与依赖

```text
房煦然（KAT/黄金/需求/契约/验收）
   │  KAT、向量、契约
   ├──────────────► 江力博（系统仿真/FPGA bring-up/Vivado/PPA）
   ├──────────────► 骆弈宾（协议/SHAKE/采样/控制）
   └──────────────► 曹子墨（低延迟 dense×sparse/RS/RM）
                         │  RTL、接口

                   江力博（xsim/板端/综合/PPA） ──► 房煦然（验收/答辩）
```

- **房煦然 → 江/骆/曹**：KAT、向量、契约、验收口径；
- **骆/曹 → 江力博**：RTL、`start/busy/done`、BRAM 接口、延迟数据；
- **江力博 → 房煦然**：进度、板端/PPA 证据、风险；
- **房煦然 → 全员**：需求、契约、验收、老师反馈。

## 五、国家级立项指标（目标）

> **国家级和校级的分水岭**：不是“有没有板子”，而是**有没有完整的 KEM + KAT + 可复现证据 + 明确的创新增量 + 与基线的量化对比**。
> 只做一个乘法器，最多是校级工作量；做到“完整 KEM + 系统协同 + 设计空间 + 差异表”，才有国家级竞争力。
>
> 目标值，不是承诺；以仿真/综合实测为准。口径分开写：仿真 / 综合 / 上板。

**组内基线（SOCC 2023）**：

| 基线 | 器件 | LUT | FF | BRAM | Fmax | KeyGen / Encap / Decap |
|:---|:---|:---|:---|:---|:---|:---|
| SOCC 2023 | xc7a200t-3 | 19,794 | 11,079 | 68 | 178 MHz | 0.11 / 0.22 / 0.38 ms |

它已经做了**稀疏乘法、RM FHT、RS ePIBM、完整 HQC-128 KEM**。本项目不能把这四项本身当原创；
差异与增量见 `docs/11_组内基线与差异表.md`。

### 5.1 功能

| 指标 | 目标 |
|:---|:---|
| 完整 RTL | HQC-128 KeyGen / Encaps / Decaps + FO + 隐式拒绝，全部 RTL |
| **完整 IP 包** | 寄存器映射 + 驱动/裸机示例 + 集成指南 + release/changelog |
| 官方 KAT | 100/100 逐字节一致 |
| **FPGA 全功能跑通** | **板端 KeyGen/Encap/Decap + KAT 100/100** |
| 单元随机 | 低延迟 dense×sparse、FHT、RS、SHAKE 各 ≥1000 组 |
| 系统仿真 | 100/100 KAT 全过 |
| 负向 | 篡改密文 → 隐式拒绝 |
| 错误数 | 0 mismatch |

### 5.2 性能/PPA

| 指标 | 目标 |
|:---|:---|
| FPGA 器件 | **AC701 XC7A200T（主）**；XC7A100T（备）；常州 200T（备用） |
| FPGA 参考 | SOCC 2023：19,794 LUT / 11,079 FF / 68 BRAM / 178 MHz |
| FPGA 目标 | **板端全功能跑通 + KAT 100/100**；记录 LUT/FF/BRAM/DSP/Fmax/cycles |
| 稀疏 vs 朴素乘法 | 周期数 ≥10×；1/2/4/8 路 Pareto |
| ASIC（条件） | **55nm 主 / 28nm 对比 / 90nm 兜底**；综合 + area/power/fmax；不流片 |

> 不承诺超过 SOCC 2023 的全硬件 KEM；我们的差异是**ASIC 多工艺 + 设计空间 + 参数化/开源可复现**。

### 5.3 成果

- 完整 RTL + KAT + **FPGA 全功能跑通 + PPA**；
- ASIC 55/28/90nm 综合评估（条件允许）；
- 可复现仓库 + 报告 + 答辩材料；
- 冲刺：论文 / 专利 / 竞赛（加分项，不是硬闸门）。

## 六、创新得分点（候选，需查新确认）

> **组内 SOCC 2023 已经做了**：稀疏乘法、RM FHT、RS ePIBM、完整 HQC-128 KEM。
> 这四项**不能**当本项目原创；下面是“论文没做/没强调”的候选增量。

| # | 候选得分点 | 为什么可能新 | 证明方式 |
|:---|:---|:---|:---|
| 1 | **ASIC 多工艺综合（55/28/90nm）** | 组内是 FPGA-only；多节点是明确差异点 | 三个节点 area/power/fmax + FPGA 对比 |
| 2 | **完整 IP 工程** | 组内是论文原型；IP 可交付是工程差异 | 寄存器/驱动/集成指南/release |
| 3 | **FPGA/ASIC 设计空间** | 组内是单一 128-bit/4-bank 配置 | 字宽/并行度/存储的 Pareto |
| 4 | **参数化/开源可复现** | 组内未强调 | HQC-128/192/256 + KAT + 脚本 + 证据链 |
| 5 | RISC-V 集成（可选） | 可编程 SoC | MMIO + KAT |
| 6 | 资源复用/恒定时间的联合评估 | 老师要求基线之上的量化评估 | 共享/独立 + 恒定时间开销对比 |
| 7 | ASIC 后端 P&R/STA（可选） | 组内是 FPGA-only | 后端报告，不流片 |

**不能写**：“首次实现 HQC 硬件”“稀疏乘法是我们的创新”“完整 KEM 是我们的创新”“FPGA 全跑通是我们的创新”“低延迟乘法结构是我们的创新”“SHAKE 复用是我们的创新”“恒定时间是我们的创新”。
**FPGA 全功能跑通是硬目标，但组内 SOCC 2023 已做；国家级增量靠完整 IP + ASIC 多工艺/设计空间/参数化/开源，后端可选。**

**查新要求**：差异表见 `docs/11_组内基线与差异表.md`；没有差异表，不写“原创”。
如果组内已经做过某项，就换角度，不要硬碰。

## 七、风险与应对

| 风险 | 应对 |
|:---|:---|
| 四人节奏不一致 | 每周集成 + 接口契约冻结 |
| KAT 对不上 | 采样/编码/填充全用官方实现 |
| 低延迟 dense×sparse 时序不收敛 | 先降频/加流水/调 LANES，再优化 |
| FHT 延迟超预算 | 全并行 → 半并行，按周期目标折中 |
| **FPGA 全功能跑通难** | AC701 200T 主；预留 4–6 周 bring-up；先仿真后上板 |
| **板卡借用冲突** | 备选 100T / 常州 200T；P0 预约 P3 窗口 |
| **ASIC 工具未确认** | 假设至少一种可用；没有就降级为 ASIC 导向 RTL + FPGA PPA |
| 原创性边界不清 | 先拿 SOCC 2023，写差异表；FPGA 全跑通是硬目标但不是唯一原创 |
| **国家级原创性风险** | ASIC 多工艺 + 设计空间 + 参数化/开源；冲刺论文/专利/竞赛 |
| 只有一台机器有 Vivado | 江力博任平台 owner，周五统一批处理；第二人装免费 Vivado BASIC 兜底 |
