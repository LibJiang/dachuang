# 团队分工与国家级指标

> 目的：把“四人怎么分工、每周怎么集成、什么算国家级立项水平”写死，避免后期扯皮。
> 配套：`README.md` §6–§7、`plan.md`、`docs/08`、`docs/09`、`docs/contracts/`。

---

## 一、总原则

1. **先完整 RTL、后 FPGA/ASIC**：先让 HQC-128 完整 RTL KEM 通过官方 KAT；FPGA 是建议阶段，ASIC 是条件阶段。
2. **接口先行**：模块 RTL 开始前，先冻结 `docs/contracts/` 对应契约。
3. **一次只动一个模块**：不要在改乘法时同时改采样/编码/字节序；每次集成只引入一个变量。
4. **证据说话**：每个结论必须有 `data/logs/` 或 `data/evidence/` 原始输出。
5. **原创性边界**：复现官方实现是基线；创新得分点必须能单独指出“哪一块是我的”（ASIC/设计空间/开源）。

## 二、四人分工

### 骆弈宾：RTL-A 协议/SHAKE/控制

**负责**

- KEM/PKE 控制 FSM：KeyGen / Encaps / Decaps、FO、隐式拒绝；
- SHAKE256 / XOF / PRNG 的 RTL；
- 固定重量采样（w/w_r/w_e）的 RTL；
- 与官方 KAT 的协议级对拍；
- 与江力博对接 KAT/向量，不维护 harness。

**交付**

- `src/kem/`、`src/sha3/`、`src/sampler/`；
- `sim/tb_sha3.v`、`sim/tb_sampler.v`、`sim/system/tb_hqc_kem.v`；
- KAT 对拍日志与向量；
- 协作纪录。

**验收**

- SHAKE/采样与官方参考一致；
- KEM 控制无死锁，`busy/done` 符合契约；
- 完整 RTL KAT 100/100。

**接口**

- 给曹子墨：控制/数据接口、字节序；
- 给江力博：KAT 对拍需求、向量格式；
- 给房煦然：接口契约输入。

---

### 曹子墨：RTL-B 算术/解码

**负责**

- `sparse_qc_mult` RTL：循环移位、XOR 累加、模 \(X^n-1\) 折叠；
- `dense_qc_mult_baseline`：朴素基线，用于加速比；
- `LANES` 参数化、BRAM banking、位置表存储；
- RS 编码 + ePIBM/BM 解码；
- RM 编码 + 128 点 FHT + 重复合并；
- 单元 testbench 与随机对拍。

**交付**

- `src/mult/`、`src/rs/`、`src/rm/`；
- `sim/tb_sparse_qc_mult*.v`、`sim/tb_rs_codec.v`、`sim/tb_rm_fht128.v`；
- 与官方向量对拍的日志；
- 1/2/4/8 路 Pareto 表。

**验收**

- 与 C 黄金逐 bit 一致（≥1000 组）；
- 稀疏 vs 朴素周期数 ≥10×；
- 4 路吞吐 ≥3×、资源 ≤2×；
- RS/RM 与官方测试向量一致；
- 契约冻结后接口不变。

**接口**

- 输入：骆弈宾的控制/向量、江力博的 KAT/黄金；
- 输出：`start/busy/done`、BRAM 接口、PPA 数据。

---

### 江力博：项目负责人 / 系统与验证

**负责**

- 进度、周报、repo/CI；与房煦然共同维护总体计划；
- **Vivado 平台 owner**：xsim 回归、OOC 综合、PPA 报告；
- 系统仿真框架：C/C++ 黄金 + KAT + RTL 对拍；
- KAT 转 RTL 向量、系统级 100/100 回归；
- ASIC 评估协调（工具/PDK/报告）；
- **不写 RTL 模块**，只做系统/验证/集成评审。

**交付**

- `models/kem/harness/`、`sim/system/`、`sim/scripts/`；
- `data/logs/`、`data/evidence/` 的 PPA/KAT 证据；
- 周报、系统仿真日志、FPGA/ASIC 报告。

**验收**

- 官方 KAT 100/100（当前已达成 pk/sk/ss）；
- xsim smoke + 系统仿真骨架；
- 每周五给出 xsim 回归 + 综合/PPA 报告；
- 不提交 RTL 模块（只 review）。

**接口**

- 给骆弈宾/曹子墨：KAT、向量、回归入口；
- 给房煦然：进度、证据、风险；
- 给老师：通过房煦然汇总技术状态。

### 房煦然：与老师对接 / 架构与验收

**负责**

- **与田老师对接**：需求/范围、ASIC 工具/PDK、板卡、时间节点；
- 总体架构与契约：`docs/08/09/12`、`docs/contracts/`；
- 原创性与差异表：SOCC 2023、ASIC、答辩口径；
- 验收清单、周会、风险跟踪；
- **不写 RTL 模块**，负责需求/架构/验收。

**交付**

- 需求/范围文档、契约冻结记录；
- 与 SOCC 2023 的差异表、验收清单；
- 周会纪要、风险清单、答辩材料。

**验收**

- 老师确认 ASIC/板卡/范围；
- 契约冻结并同步全员；
- 差异表能回答“创新点是什么”；
- 每周验收清单有更新。

**接口**

- 给全员：需求、契约、验收口径；
- 给江力博：进度/证据要求；

## 三、接口与依赖

```text
江力博（KAT/黄金/系统仿真/Vivado）
   │  向量、KAT、回归入口
   ├──────────────► 骆弈宾（协议/SHAKE/采样/控制）
   └──────────────► 曹子墨（稀疏乘法/RS/RM）
                         │  RTL、接口、PPA
                         ▼
                   江力博（xsim/综合/PPA） ──► 房煦然（需求/契约/验收/答辩）
```

- **江力博 → 骆/曹**：KAT、向量、回归入口、接口契约；
- **骆/曹 → 江力博**：RTL、`start/busy/done`、BRAM 接口、延迟数据；
- **江力博 → 房煦然**：进度、证据、PPA/ASIC 数据；
- **房煦然 → 全员**：需求、契约、验收口径、老师反馈。

### Vivado 平台 owner（江力博）

- 维护 `sim/run.ps1`、`sim/scripts/run_xsim.tcl`、`build/constraints/`；
- 每周五统一跑 xsim 回归 + OOC 综合，归档到 `data/logs/`、`data/evidence/`；
- 其他人用 iverilog/Verilator 做本地快速检查，**最终以江力博的 xsim/综合日志为准**；
- 单点风险：只有一台 Vivado。建议第二人安装免费 Vivado BASIC，或至少备份工程/脚本/约束。

## 五、国家级立项指标（目标）

> **国家级和校级的分水岭**：不是“有没有板子”，而是**有没有完整的 KEM + KAT + 可复现证据 + 明确的创新增量 + 与基线的量化对比**。
> 只做一个乘法器，最多是校级工作量；做到“完整 KEM + 系统协同 + 设计空间 + 差异表”，才有国家级竞争力。
>
> 目标值，不是承诺；以仿真/综合实测为准。口径分开写：仿真 / 综合 / 上板。

**组内基线（SOCC 2023）**：

| 基线 | 器件 | LUT | FF | BRAM | Fmax | KeyGen / Encap / Decap |
|:---|:---|:---|:---|:---|:---|:---|
| SOCC 2023 | xc7a200t-3 | 19,794 | 11,079 | 68 | 178 MHz | 0.11 / 0.22 / 0.38 ms |

它已经做了**稀疏乘法、RM FHT、RS ePIBM、完整 HQC-128 KEM**。本项目不能把这四项本身当原创；
差异与增量见 `docs/11_组内基线与差异表.md`。

### 5.1 功能

| 指标 | 目标 |
|:---|:---|
| 完整 RTL | HQC-128 KeyGen / Encaps / Decaps + FO + 隐式拒绝，全部 RTL |
| 官方 KAT | 100/100 逐字节一致 |
| 单元随机 | 稀疏乘法、FHT、RS、SHAKE 各 ≥1000 组 |
| 系统仿真 | 100/100 KAT 全过 |
| 负向 | 篡改密文 → 隐式拒绝 |
| 错误数 | 0 mismatch |

### 5.2 性能/PPA

| 指标 | 目标 |
|:---|:---|
| FPGA 器件 | PYNQ-Z2 xc7z020 或实验室更大器件 |
| FPGA 参考 | SOCC 2023：19,794 LUT / 11,079 FF / 68 BRAM / 178 MHz |
| FPGA 目标 | 先“能放、能跑、KAT 过”，记录 LUT/FF/BRAM/DSP/Fmax/cycles |
| 稀疏 vs 朴素乘法 | 周期数 ≥10×；1/2/4/8 路 Pareto |
| ASIC（条件） | 综合 + area/power/fmax；不跑 P&R、不流片 |
| 上板 | 可选，不是 V0 闸门 |

> 不承诺超过 SOCC 2023 的全硬件 KEM；我们的差异是**完整 RTL + ASIC 评估 + 设计空间 + 开源可复现**。

### 5.3 成果

- 完整 RTL + KAT + FPGA PPA；
- ASIC 综合评估（条件允许）；
- 可复现仓库 + 报告 + 答辩材料；
- 冲刺：论文 / 专利 / 竞赛（加分项，不是硬闸门）。

## 六、创新得分点（候选，需查新确认）

> **组内 SOCC 2023 已经做了**：稀疏乘法、RM FHT、RS ePIBM、完整 HQC-128 KEM。
> 这四项**不能**当本项目原创；下面是“论文没做/没强调”的候选增量。

| # | 候选得分点 | 为什么可能新 | 证明方式 |
|:---|:---|:---|:---|
| 1 | **完整 RTL + ASIC 评估** | 组内是 FPGA-only；ASIC 是明确差异点 | ASIC area/power/fmax + FPGA 对比 |
| 2 | **FPGA/ASIC 设计空间** | 组内是单一 128-bit/4-bank 配置 | 字宽/并行度/存储的 Pareto |
| 3 | **开源可复现** | 组内未强调 | 官方 KAT + RTL + 脚本 + 证据链 |
| 4 | RISC-V 集成（可选） | 可编程 SoC | MMIO + KAT |
| 5 | 恒定时间/故障检测（选做） | 组内未涉及 | 侧信道/故障注入实验 |

**不能写**：“首次实现 HQC 硬件”“稀疏乘法是我们的创新”“完整 KEM 是我们的创新”。

**查新要求**：差异表见 `docs/11_组内基线与差异表.md`；没有差异表，不写“原创”。
如果组内已经做过某项，就换角度，不要硬碰。

## 七、风险与应对

| 风险 | 应对 |
|:---|:---|
| 四人节奏不一致 | 每周集成 + 接口契约冻结 |
| KAT 对不上 | 采样/编码/填充全用官方实现 |
| 稀疏乘法时序不收敛 | 先降频/加流水，再优化 |
| FHT 延迟超预算 | 全并行 → 半并行，按周期目标折中 |
| 上板条件不确定 | 上板设为最后可选项；仿真/综合先交付 |
| 原创性边界不清 | 先拿 SOCC 2023，写差异表；不把复现当原创 |
| 只有一台机器有 Vivado | 江力博任平台 owner，周五统一批处理；第二人装免费 Vivado BASIC 兜底 |
