# 组内基线与差异表：SOCC 2023 HQC 硬件实现

> 论文：Chen Li, Suwen Song, Jing Tian, Zhongfeng Wang, Çetin Kaya Koç,
> **An Efficient Hardware Design for Fast Implementation of HQC**, IEEE SOCC 2023.
> DOI：`10.1109/SOCC58585.2023.10257054`
> 本地 PDF：桌面（不入库，注意版权）。
>
> **结论先行**：组内这篇论文已经做了
> **稀疏乘法 + RM FHT 解码 + RS ePIBM 解码 + 完整 HQC-128 KEM**。
> 所以本项目**不能**把“稀疏乘法”“完整 KEM”“FHT 解码”本身当作原创。
> 我们的创新必须落在**系统形态、设计空间、参数化、软硬协同、安全性或可复现流程**上。

## 一、论文做了什么

| 项 | 内容 |
|:---|:---|
| 目标 | HQC-128 完整 KEM（KeyGen / Encaps / Decaps） |
| 器件 | Xilinx Artix-7 `xc7a200t-3` |
| 乘法 | 稀疏乘法 \(O(n\omega)\)；128-bit 操作数；4 个 RAM A bank；每个位置 139 周期 |
| RM 解码 | Fast Hadamard Transform（FHT） |
| RS 解码 | enhanced Parallel Inversionless Berlekamp-Massey（ePIBM） |
| SHAKE | 共享 SHAKE256，双时钟（SHAKE 低频、其余高频） |
| 乘法模块 | 2,239 LUT / 612 FF / 4 BRAM / 198 MHz / 10,921 cycles / 55.16 µs |
| KeyGen 模块 | 2,813 LUT / 1,318 FF / 10 BRAM / 172 MHz / 16,188 cycles / 94.12 µs |
| Encryption 模块 | 2,716 LUT / 1,894 FF / 13 BRAM / 192 MHz / 24,016 cycles / 125 µs |
| Decryption 模块 | 6,641 LUT / 5,466 FF / 13 BRAM / 187 MHz / 14,769 cycles / 78.97 µs |
| 完整 KEM | 19,794 LUT / 11,079 FF / 68 BRAM / 178 MHz |
| 完整 KEM 时间 | KeyGen 0.11 ms / Encaps 0.22 ms / Decaps 0.38 ms（摘要口径） |
| 相对 [6] | 乘法周期 −42%；Decryption ADP −25% |

> 说明：Table II 的列序在 PDF 文本抽取时有歧义；完整 KEM 时间以论文摘要为准。
> 论文只实现了 HQC-128，但声称方法可用于 HQC-192/256。

## 三、差异表

| 维度 | SOCC 2023（组内） | 本项目（建议） | 差异/卖点 |
|:---|:---|:---|:---|
| 器件 | Artix-7 `xc7a200t-3`（大器件） | PYNQ-Z2 `xc7z020`（53K LUT / 140 BRAM） | 资源受限边缘平台 |
| 系统形态 | 固定硬件 KEM | **自研 RISC-V + HQC 协处理器**（V1） | 可编程、可调度、可扩展 |
| 软硬划分 | 全硬件（含 SHAKE/RS） | V0 混合：C/C++ SHAKE/RS + PL 稀疏乘法/FHT | 快速验证 + 资源更省 |
| 乘法 | 单一 128-bit / 4 bank 配置 | 参数化 64/128-bit、1/2/4/8 路、BRAM banking | **设计空间/Pareto** |
| 解码 | ePIBM RS + FHT RM | V0 复用 C/C++ RS；PL 做 FHT | 不拼 RS 面积，拼系统 |
| 参数集 | 只实现 HQC-128 | HQC-128 先行，192/256 参数化（选做） | 参数化 |
| 验证 | 论文级实验 | C/RTL 协同仿真 + 官方 KAT + 0 mismatch | **可复现 + 完整证据链** |
| 安全 | 未涉及 | 可选：恒定时间/故障检测 | 进阶原创点 |
| 评价 | 速度/面积 ADP | 资源受限平台 + 可编程性 + 设计空间 | 换赛道，不硬拼绝对速度 |

## 四、推荐的原创定位

### 方案 A（最推荐）：自研 RISC-V + HQC 协处理器

> “面向自研 RISC-V 的可配置 HQC KEM 协处理器：稀疏乘法设计空间 + 完整 KEM 软硬协同”

- 论文是**固定硬件 KEM**；我们把它变成**可编程 SoC 里的协处理器**；
- 复用你竞赛的 RV32IM 核、MMIO/AXI 经验；
- 核负责调度/采样/SHAKE/RS（或部分软件），PL 负责稀疏乘法/FHT；
- 原创点：系统集成、指令/寄存器接口、软硬划分量化、可编程性；
- 风险：裸机集成工作量大；V0 先用 C/C++ 跑通，V1 再接核。

### 方案 B：面向 Zynq-7020 的参数化设计空间

> “资源受限 FPGA 上的 HQC 稀疏乘法/解码器设计空间与 Pareto 分析”

- 论文是单一配置；我们做 64/128-bit、1/2/4/8 路、不同 BRAM banking；
- 给出面积-周期-Pareto，回答“在 7020 上怎么选”；
- 原创性中等，但工作量可控、数据好看；
- 适合和 A 组合。

### 方案 C：恒定时间/故障检测（进阶）

- 论文不涉及侧信道；做恒定时间稀疏乘法、FHT/RS 故障检测；
- 与田老师组侧信道方向对口；
- 风险：需要功耗采集/统计评估，本科一年偏难。

### 方案 D：HQC-192/256 参数化

- 论文只做 HQC-128，声称可扩展；
- 做全参数集参数化 + 资源/延迟对比；
- 增量明显，但单独撑“国家级”偏弱，建议作为 A/B 的附带成果。

**推荐组合：A + B**（RISC-V 系统集成 + 设计空间），资源/时间允许再带 C 或 D。

## 五、指标修订建议

> 不要直接和论文比“全硬件绝对延迟”：论文在更大的 Artix-7 上、全硬件 KEM。
> 我们的比较口径应是：**资源受限平台 + 可编程性 + 设计空间 + 完整 KAT**。

| 指标 | 论文基线 | 本项目目标（建议） |
|:---|:---|:---|
| 器件 | xc7a200t-3 | xc7z020（PYNQ-Z2） |
| 完整 KEM | 19,794 LUT / 11,079 FF / 68 BRAM / 178 MHz | V0 混合：PL ≤10k LUT、≤20 BRAM、≥100 MHz |
| KEM 时间 | 0.11 / 0.22 / 0.38 ms | 测混合架构端到端；不承诺超过论文全硬件 |
| 乘法 | 10,921 cycles / 2,239 LUT / 4 BRAM | 参数化 1/2/4/8 路；给出 Pareto |
| 功能 | HQC-128 完整 KEM | 官方 KAT 100/100；≥10 组协同仿真；0 mismatch |
| 系统 | 固定硬件 | RISC-V + PL 协处理器（V1） |
| 原创 | 稀疏乘法 + 解码 + 全硬件 | RISC-V 集成 + 设计空间 + 混合协同 |

**国家级立项的关键**：不是“比论文快”，而是“在论文没做的系统/设计空间/可编程性上做出可验证的增量”，并配论文/专利/竞赛冲刺。

## 六、立项书怎么写

1. **明确引用**：把 SOCC 2023 作为直接基线，写清它已经做了什么。
2. **明确边界**：
   - 复现：稀疏乘法、FHT、完整 KEM 流程；
   - 改进：参数化/设计空间、混合软硬划分；
   - 原创：RISC-V 协处理器集成、量化软硬协同、可选恒定时间。
3. **不要写**：
   - “首次实现 HQC 硬件”；
   - “稀疏乘法是我们的创新”；
   - “完整 KEM 是我们的创新”。
4. **差异表**：直接把本文第三节放进立项书/答辩 PPT。
