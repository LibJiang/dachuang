# 新队友阅读顺序（小白不迷路版）

> 给刚加入大创组的同学：按这个顺序读，不会迷路。
> 原则：**先会用工具 → 再懂方向 → 再选题目 → 最后补知识**。不要一上来就啃论文。

---

## 二、逐步说明（每步都有"读完要能做到"）

### 第 1 步：README（约 5 分钟）

- **看什么**：项目是做什么的、仓库里有哪些文档、当前计划。
- **可以跳过**：无。
- **读完要能做到**：说出仓库里有哪几份文档、当前进度到哪。
- **建议**：先点开 4 个文档的标题，大致知道每份是干嘛的，再按顺序深入。

### 第 2 步：`docs/04_GitHub与Git一天上手指南.md`（半天 ~ 1 天）

- **为什么排第二**：不会 Git，就无法 clone、提交、发 PR，后面的协作你都参与不了。
- **重点看**：第 2 关（克隆）、第 3 关（提交）、第 4 关（推送/拉取）、第 5 关（分支与 PR）。
- **可以跳过**：第 7 关（撤销）先了解即可，遇到问题再回来看。
- **读完要能做到**：独立完成"克隆 → 改文件 → 提交 → 推送 → 开分支 → 发 PR → 解决一次冲突"。
- **过关标准**：完成该文档的「结业任务」，GitHub 上能看到你的 PR 已合并。
- **提醒**：先让管理员把你加成 Collaborator，否则只能 Fork + PR。

### 第 3 步：`docs/01_田静老师资料与研究方向.md`（1~2 小时）

- **看什么**：
  - 第一节「导师档案」：她是谁、做什么。
  - 第二节「研究方向拆解」：后量子密码硬件、AI 同态安全、区块链硬件、纠错码。
  - 第五节「进组阅读顺序」：论文怎么排。
  - 第六节「两篇入门论文」：只有数电基础也能读。
- **可以跳过**：第四节 33 篇论文**不要一次全读**，先记住分类，后续按需查。
- **读完要能做到**：说出她的 4 个研究方向，并记住 2 篇入门论文的标题和一句话结论。
- **建议**：把 33 篇论文清单当成"字典"，不是"小说"。

### 第 4 步：`docs/02_大创推荐选题.md`（约 1 小时）

- **看什么**：开头的选题总览表 + T1、T2、T5 三个推荐选题。
- **可以跳过**：暂时不看 T3/T4/T6 的细节（除非你明确想做安全 / 同态 / 纠错码）。
- **读完要能做到**：
  - 选出 1 个候选选题；
  - 用 3 句话说明"为什么选它、它解决什么问题、需要什么基础"。
- **建议**：基础弱优先 T1；会 Verilog 想冲成果选 T2；想做完整系统选 T5。

### 第 5 步：`docs/03_前置知识与学习路线.md`（约 2 小时）

- **看什么**：知识地图、分模块资源网址、6 个月时间表、第一个动手项目。
- **可以跳过**：硬件安全、体系结构部分先略读。
- **读完要能做到**：
  - 写出一份自己的「1 个月学习计划」；
  - 注册 HDLBits 并完成前 5 道题；
  - 装好 Vivado / 仿真器（PYNQ-Z2 视条件可选）。
- **建议**：先抓"Verilog + 模运算 + NTT 硬件"三样，别贪多。

### 第 6 步：`docs/05_前置知识补全_从数电到Verilog实战.md`（4 周，边读边做）

- **为什么加这一步**：本批队员大多学过数电但没写过 Verilog，只读路线不够，必须补工程基础。
- **重点看**：第 1 节硬件思维、第 2 节知识清单、第 4 节 Verilog 最小子集、第 5 节四周计划。
- **可以跳过**：第 6 节选题映射先扫一眼，选定选题后再细看。
- **读完要能做到**：独立写出带自检 testbench 的小模块，跑通一次仿真和一次 Vivado 综合。
- **复用提醒**：第 3 节列了 FPGA 仓库可复用的资产，只复用写法、流程和规范，不要照搬业务 RTL。

### 第 7 步：`docs/06_协作纪录与技能提炼规范.md`（10 分钟，之后每次工作都执行）

- **为什么加这一步**：团队要能复盘、能交接、能把个人经验提炼成 skill，必须从第一天开始留痕。
- **重点看**：第 1 节硬性规则、第 3 节必填字段、第 6 节从纪录提炼 skill 的流程。
- **读完要能做到**：复制 `docs/records/TEMPLATE.md`，在每次工作结束后写一篇合格纪录。
- **硬约束**：没有协作纪录的 PR 不合入；没有验证证据的纪录不算完成。

### 第 8 步：`docs/07_新手使用Agent教程.md`（1~2 小时，六个门槛）

- **为什么加这一步**：Agent 能大幅提高效率，但不会用就会「只在聊天里出代码、仓库没变化、看不懂也提交」。
- **重点看**：第 2 节六个门槛、第 3 节对话姿势、第 4 节安全边界。
- **读完要能做到**：让 Agent 直接改工作区文件，在 VS Code 看见 diff，跑出验证证据，再提交。
- **硬约束**：Agent 说「完成」不算数，必须自己在 VS Code 和终端复现一次。

## 三、按目标选择快捷路线

| 你的目标 | 推荐顺序 |
|---|---|
| 想尽快进组、准备面试 | 01（重点第二、六节）→ 02（选 T1）→ 03（只读第一阶段） |
| 想马上动手写代码 | 04 → 03（HDLBits + Verilog）→ 01（只读两篇入门论文） |
| 想写立项书 / 答辩 | 01 → 02（选一个 + 套立项书结构）→ 03（只列所需知识） |
| 什么都不确定 | 就按上面的默认顺序走 |

## 四、阅读方法（很重要）

1. **先粗读，再精读**：先看目录、标题、图表，知道全貌，再逐节细读。
2. **带着问题读**：读论文前先问"它解决什么问题？用了什么方法？结果好多少？"读完写 3 行笔记。
3. **数学看不懂先跳过**：先抓住数据通路、架构图、PPA 对比表。
4. **不要只收藏不读**：每天固定 1 小时，比周末突击 8 小时有效。
5. **读完就动手**：每读完一块，就用 Verilog / Python 做一个小实验。

## 五、第一个里程碑（加入后 1~2 周内完成）

- [ ] 完成 Git 结业任务，至少合并 1 个 PR
- [ ] 在 `docs/` 下建立 `notes-你的名字.md` 学习笔记
- [ ] 从 02 里选定 1 个候选选题
- [ ] 注册 HDLBits 并完成前 5 题
- [ ] 读完 01 里的 2 篇入门论文，各写 3 行笔记
- [ ] 用 `docs/records/TEMPLATE.md` 写第一篇协作纪录并随 PR 提交

全部打勾，你就正式"上车"了。

## 六、避坑清单

1. **不要一上来读 33 篇论文**——会劝退，先读 2 篇入门论文。
2. **不要先啃抽象代数和格密码证明**——组里做硬件，不是纯理论。
3. **不要跳过 Git 直接改代码**——不会提交和 PR，等于没参与。
4. **不要在 `main` 上直接改大功能**——先开分支。
5. **不要只收藏资料不动手**——Verilog 必须写，HDLBits 比看十门课有用。
6. **遇到不懂的，先查文档再问人**，提问时带上"我试了什么、卡在哪"。
