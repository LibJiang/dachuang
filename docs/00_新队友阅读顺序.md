> 给刚加入大创组的同学：按这个顺序读，不会迷路。
> 原则：**先会用工具 → 再懂方向 → 再读技术路线 → 再补知识**。不要一上来就啃 33 篇论文。
> **方向已确定：HQC KEM 硬件加速。** **策略：先完整 RTL + KAT，再 FPGA 全功能跑通；ASIC 只做综合、不流片。**
> **开工前先读 [开发流程与硬约束](workflow.md)：没有冻结契约，不许写代码；单步 ≤100 行；commit 前 3 题。**

## 二、逐步说明（每步都有“读完要能做到”）

### 第 1 步：README（约 5 分钟）

- **看什么**：项目目标、HQC 方向、三步走、国家级指标、四人分工、仓库结构、当前状态。
- **读完要能做到**：一句话说清“我们在 HQC KEM 里做什么、为什么先仿真后上板”。

### 第 2 步：`docs/04_GitHub与Git一天上手指南.md`（半天 ~ 1 天）

- **为什么排第二**：不会 Git，就无法 clone、提交、发 PR。
- **重点看**：克隆、提交、推送/拉取、分支与 PR。
- **读完要能做到**：独立完成“克隆 → 改文件 → 提交 → 推送 → 开分支 → 发 PR → 解决一次冲突”。
- **过关标准**：完成该文档的「结业任务」，GitHub 上能看到你的 PR 已合并。

### 第 3 步：`docs/01_田静老师资料与研究方向.md`（1~2 小时）

- **看什么**：导师档案、研究方向拆解、进组阅读顺序、两篇入门论文。
- **重点**：论文 #15（SOCC 2023 HQC 硬件实现）——这是本项目最直接的技术基线，必须读。
- **可以跳过**：33 篇论文不要一次全读，先记住分类。
- **读完要能做到**：说出她 4 个研究方向；说清 HQC 与 Kyber 的区别。

### 第 4 步：`docs/08_HQC技术路线.md`（2~3 小时）

- **看什么**：HQC 参数、KEM 流程、瓶颈、稀疏乘法、软硬划分、原创点。
- **重点**：为什么 dense × sparse 能降到 $O(wn)$；V0 为什么先做 HQC-128。
- **读完要能做到**：
  - 画出 KeyGen / Encaps / Decaps 的数据流；
  - 说出 PL/RTL 和 C/C++ 各承担什么；
  - 说出你的创新得分点与组内 SOCC 2023 论文的差异。

### 第 5 步：`docs/09_工程约束与验证规范.md`（1 小时，动手前必读）

- **看什么**：数据表示、Verilog-2001 约束、握手、C/C++ 黄金、xsim、验证闸门、证据规则。
- **读完要能做到**：写出一个符合规范的模块端口和 testbench 自检框架。
- **硬约束**：位序、稀疏位置表、KAT 字节序、`PASS/FAIL` 输出，全部按文档执行。

### 第 6 步：`docs/10_团队分工与国家级指标.md`（30 分钟）

- **看什么**：四人分工、接口依赖、周节奏、国家级指标、创新得分点。
- **读完要能做到**：说清自己负责哪一块、和谁对接、本周交付什么。
- **注意**：目标值是“目标”，最终以仿真/综合实测为准。

### 第 7 步：`docs/11_组内基线与差异表.md`（30 分钟）

- **看什么**：组内 SOCC 2023 已经做了什么、哪些不能当原创、我们的候选增量。
- **读完要能做到**：说出“稀疏乘法/完整 KEM/FHT/RS 都不是我们的原创”，并说出至少 1 个可行增量。
- **硬约束**：立项书/答辩必须引用差异表，不写“首次实现 HQC 硬件”。

### 第 8 步：`docs/12_FPGA_ASIC路线.md`（30 分钟）

- **看什么**：完整 RTL、FPGA 原型、ASIC 综合评估的边界和里程碑。
- **读完要能做到**：说清 V0 全 RTL、V1 FPGA、V2 ASIC 条件阶段分别做什么。
- **硬约束**：先完整 RTL + KAT；上板/ASIC 是后置/条件，不是 V0 闸门。

### 第 9 步：`docs/13_开工清单与近期任务.md`（30 分钟）

- **看什么**：四人分工、开工清单、这几天任务、验收标准。
- **读完要能做到**：说清自己这周交付什么、验收标准是什么。
- **硬约束**：没有证据不算完成；RTL 线由骆弈宾/曹子墨负责。

### 第 10 步：`docs/03_前置知识与学习路线.md`（约 2 小时）

- **看什么**：知识地图、资源、6 个月时间表、第一个动手项目。
- **读完要能做到**：写出一份自己的「1 个月学习计划」；装好 Vivado / 仿真器。

### 第 11 步：`docs/05_前置知识补全_从数电到Verilog实战.md`（4 周，边读边做）

- **重点**：硬件思维、Verilog 最小子集、四周计划、自检 testbench。
- **读完要能做到**：独立写出带自检 testbench 的小模块，跑通一次 xsim 仿真和一次 Vivado 综合。
- **复用提醒**：只复用 FPGA 仓库的写法、流程和规范，不要照搬业务 RTL。

### 第 12 步：`docs/06_协作纪录与技能提炼规范.md`（10 分钟，之后每次工作都执行）

- **硬约束**：没有协作纪录的 PR 不合入；没有验证证据的纪录不算完成。
- **读完要能做到**：复制 `report/llm_log/TEMPLATE.md`，写一篇合格纪录。

### 第 13 步：`docs/07_新手使用Agent教程.md`（1~2 小时，六个门槛）

- **重点**：六个门槛、对话姿势、安全边界。
- **硬约束**：Agent 说“完成”不算数，必须自己在 VS Code 和终端复现一次。

## 四、阅读方法

1. **先粗读，再精读**：先看目录、标题、图表，再逐节细读。
2. **带着问题读**：它解决什么问题？用了什么方法？结果好多少？读完写 3 行笔记。
3. **数学看不懂先跳过**：先抓住数据通路、架构图、PPA 对比表。
4. **不要只收藏不读**：每天固定 1 小时，比周末突击 8 小时有效。
5. **读完就动手**：每读完一块，就用 C / Verilog 做一个小实验。

## 六、避坑清单

1. **不要一上来读 33 篇论文**——先读 #15（HQC 硬件）和 #6（模约减方法论）。
2. **不要先啃抽象代数**——组里做硬件，先把数据流和位宽搞清楚。
3. **不要跳过 Git 直接改代码**——不会提交和 PR，等于没参与。
4. **不要在 `main` 上直接改大功能**——先开分支。
5. **不要只收藏资料不动手**——C 黄金和 Verilog 必须写。
6. **不要自己发明采样器/字节序**——KAT 会对不上；以官方参考实现为准。
7. **不要先纠结上板**——先把完整 KEM 在 C/C++ + xsim + 综合里跑通。
