# 新手使用 Agent 教程（VSCode + 本仓库）

> **目标**：让新队员在 1~2 小时内学会用 AI Agent 在本仓库干活，并且每一步都能在 VS Code 里看见、能复现、能提交。
> **三条原则**：
> 1. **必须在工作区留下痕迹**：Agent 要直接改仓库里的文件，不能只在聊天里贴代码。
> 2. **小步走**：一次只做一件事，每步都要验收。
> 3. **看不懂不提交**：能跑不是标准，讲得清才是。
> **配套**：协作纪录见 `docs/06_协作纪录与技能提炼规范.md`；Verilog 基础见 `docs/05_前置知识补全_从数电到Verilog实战.md`。

---

## 0. 先把 Agent 当成什么

| 你以为是 | 实际上是 |
|---|---|
| 一个更聪明的搜索框 | 一个能**读写文件、跑命令、改仓库**的助手 |
| 问一句就自动做完 | 需要你给目标、给约束、给验收标准 |
| 它说完成就完成了 | 必须看 diff、看命令输出、自己复现 |

Agent 能帮你：读代码、写文档、改代码、跑测试、整理 Git 提交。
Agent 不能替你：理解原理、做技术决策、保证结果正确。

> **铁律**：Agent 改了哪些文件，你必须在 VS Code 的「资源管理器」和「源代码管理」里亲眼看到。

## 2. 六个门槛（一个一个过）

每个门槛都有：**目标 → 操作 → 验收 → 常见错误**。没过完不要跳。

### 门槛 1：只读模式，让 Agent 讲清仓库

- **目标**：不改任何文件，让 Agent 说明仓库结构。
- **操作**：对 Agent 说：

  ```
  只读，不要修改任何文件。请阅读 README.md 和 docs/ 下的文档，
  告诉我：1) 仓库有哪几份文档；2) 当前 git 分支和状态；3) 新手应该按什么顺序读。
  ```

- **验收**：你能不看屏幕复述出「有几份文档、当前分支、阅读顺序」。
- **常见错误**：一上来就让 Agent「帮我重构项目」。先学会读，再学会改。

---

### 门槛 2：让 Agent 改一篇文档，并在 VS Code 看见 diff

- **目标**：做一个小改动，亲眼看到文件变化。
- **操作**：对 Agent 说：

  ```
  请直接修改仓库里的 report/llm_log/TEMPLATE.md（不要只在聊天里贴代码）。
  在「参考」一栏下面加一行示例说明。
  改完告诉我：改了哪个文件、改了哪几行。
  ```

- **验收**：
  - VS Code 资源管理器里文件有「已修改」标记
  - 源代码管理面板里能看到 diff
  - diff 只有你要求的改动，没有多余内容
- **常见错误**：Agent 只在聊天里给代码，仓库文件没变。此时要求它「直接写入文件」。

---

### 门槛 3：让 Agent 跑命令，并给出原始输出

- **目标**：确认 Agent 的结论有证据。
- **操作**：

  ```
  请在仓库根目录运行 git status 和 git diff --check，
  把完整的原始输出贴给我，不要总结。
  ```

- **验收**：你能在终端/输出里看到真实命令和真实结果。
- **常见错误**：接受「应该没问题」「已经验证」但没有输出。**没有原始输出就不算验证。**

---

### 门槛 4：分支 + 提交 + 推送

- **目标**：完整走一遍 Git 协作。
- **操作**：

  ```
  请帮我：1) 新建分支 feat/agent-practice；
  2) 展示 git diff 和 git status；
  3) 等我确认后再 commit；
  4) commit 后 push 到 origin。
  ```

- **验收**：
  - `git branch` 能看到新分支
  - 提交信息说清做了什么
  - GitHub 上能看到这次提交
- **常见错误**：在 `main` 上直接改大功能；不看 diff 就提交；提交了密钥或生成物。

---

### 门槛 5：写一篇协作纪录

- **目标**：按模板留下可复现的记录。
- **操作**：

  ```
  请按 report/llm_log/TEMPLATE.md，帮我把今天这次练习写成一篇协作纪录，
  文件名按规范放在 report/llm_log/ 下。必须包含验证命令和原始结果。
  ```

- **验收**：
  - 有命令、有原始结果、有待办、有可提炼经验
  - 和本次代码/文档在同一个分支或 PR
- **常见错误**：只写「今天学习了 Agent」，没有证据。

---

### 门槛 6：独立完成一个小任务（结业）

- **目标**：不看教程，自己完整走一遍。
- **任务示例**：写一个参数化计数器 + 自检 testbench，仿真 PASS，写协作纪录，提 PR。
- **验收清单**：
  - [ ] Agent 直接改了工作区文件
  - [ ] 你在源代码管理里看过 diff
  - [ ] 仿真/脚本有 PASS 证据
  - [ ] 有协作纪录
  - [ ] 提交/PR 已推送
  - [ ] 你能讲清这段代码在干什么

全部通过，你就「能独立用 Agent 干活」了。

## 3. 和 Agent 对话的正确姿势

### 3.1 一个好请求的四要素

| 要素 | 说明 | 例子 |
|---|---|---|
| 目标 | 要达成什么 | 「给计数器的 testbench 加随机向量对拍」 |
| 上下文 | 涉及哪些文件 | 「`src/arith/counter.v` 和 `sim/tb_counter.v`」 |
| 约束 | 不能做什么 | 「不改接口，不引入新依赖，单步 ≤100 行」 |
| 验证 | 怎么算成功 | 「Vivado xsim 跑出 `PASS: 1024/1024 checks`」 |

### 3.2 正例 vs 反例

| 反例 | 正例 |
|---|---|
| 「帮我优化一下代码」 | 「只优化 `sparse_qc_mult.v` 的关键路径，不改接口，综合后 WNS 要 ≥ 0」 |
| 「写个稀疏乘法」 | 「先给步骤清单，再实现 dense×sparse 的移位/XOR/折叠，配自检 tb，用 1024 组随机向量对拍」 |
| 「都改好，提交吧」 | 「先给 diff 和验证结果，我确认后再提交」 |

### 3.3 三条对话习惯

1. **先要计划，再要代码**：让它先列步骤，你确认后再动手。
2. **一次一件事**：改文档就改文档，别顺手改代码。
3. **要求证据**：命令 + 原始输出 + diff，缺一不可。

## 4. 安全与边界（必须遵守）

- **不粘贴密钥**：密码、token、私钥不要发进对话。
- **删除/破坏性操作先确认**：删文件、改历史、`push --force` 必须先问队友。
- **不用工作区外临时文件**：验证必须在仓库内可复现。
- **生成物不入库**：`.vvp`、`__pycache__`、Vivado 中间产物不要提交。
- **提交前必须看 diff**：确认没有多余改动和敏感信息。
- **Agent 说「已完成」不算数**：你自己复现一次才算。

## 5. 每次干活的固定流程（贴在桌前）

```
1. 说清目标（一句话）
2. 让 Agent 给步骤清单
3. 小步执行（单步 ≤100 行）
4. 在 VS Code 看 diff
5. 跑验证，看原始输出
6. 写协作纪录
7. 提交 / 发 PR
8. 看不懂就让它讲，直到你能复述
```

---

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| Agent 说改好了，VS Code 没变化 | 要求它「直接写入仓库文件」，并给出完整路径 |
| Agent 能跑命令，你终端跑不了 | 工作目录/环境不同；要求给出完整命令和工作目录 |
| 一次改太多，看不懂 | 要求拆步，单步 ≤100 行 |
| 不知道它对不对 | 让它贴 `git diff` 和验证输出 |
| 看不懂某段代码 | 让它逐段讲设计意图，并出 2~3 道理解题 |
| 提交错了 | 不要 force push；先问队友，用新提交修复 |
| 不确定该不该做 | 先写进协作纪录的「待办」，例会上讨论 |

## 8. Prompt 模板库（直接复制改）

**读代码**

```
只读，不改文件。请讲清 <文件/模块> 的输入输出、关键信号、时序边界，
并指出我作为初学者最容易看错的 3 个地方。
```

**改文档**

```
请直接修改 <文件路径>，在 <位置> 增加 <内容>。
改完给出 diff 摘要，不要改其他文件。
```

**改代码**

```
目标：<一句话>。
范围：只改 <文件列表>，不改接口。
约束：单步 ≤100 行，Verilog-2001 可综合子集。
验证：<命令> 要输出 <期望结果>。
先给步骤清单，我确认后再动手。
```

**调试**

```
现象：<报错/错误结果>。
请先复现并贴原始输出，再定位原因；
给出最小修复，并说明为什么这样修。
```

**写测试**

```
请为 <模块> 写自检 testbench：
覆盖正常路径、复位、边界值；随机向量 1024 组；
统一打印 PASS/FAIL + 用例数 + 错误数。
```

**提交前检查**

```
提交前请给我：1) git status；2) git diff；3) 验证命令与原始结果；
4) 未完成项。确认没有生成物和敏感信息后，再等我决定是否 commit。
```
