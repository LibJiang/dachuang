## 二、数据表示（最容易错）

### 2.1 稠密多项式

- n bit，`bit i` 表示 $X^i$ 的系数；
- bit 0 是最低位；十六进制字符串最右边的 nibble 对应 bit 0–3；
- 例：n=8，`0x4D` = `0100_1101` = $1 + X^2 + X^3 + X^6$；
- n 不是 64 的倍数时，高位补 0，但**逻辑长度必须严格为 n**；
- 所有模块必须显式携带 `N` 参数，不得写死 17669。

### 2.2 稀疏多项式

- 位置列表：`pos[0..W-1]`，每个元素 $0 \le p < n$；
- **升序、无重复**；重量 W 为参数；
- 稀疏乘法的语义：$\bigoplus_{p} (a \lll p) \bmod (X^n-1)$；
- 位置表是**秘密数据**：不得打印、不得用位置值做分支或地址相关的可观察时序（V0 至少文档标注）。

### 2.3 字节序与 KAT

- 官方 KAT 的字节序、位序、填充规则**一律以官方参考实现为准**；
- 不得自行定义“更顺手”的字节序；
- 任何与官方不一致的转换，必须在 `docs/contracts/hqc_kem_v0.md` 写明，并有对拍证据。

## 三、RTL 编码约束

1. **Verilog-2001**：综合 RTL 禁止 `.*`、`logic`、`always_ff`、`always_comb`、`interface` 等 SystemVerilog-only 语法。
2. **禁止 latch**：组合 `always @*` 所有分支必须赋值；需要默认值。
3. **时钟/复位**：同步设计；异步复位低有效 `rst_n`；跨时钟域必须显式同步器 + 注释。
4. **位宽显式**：禁止隐式截断/扩展；有符号运算显式 `signed` / `$signed`。
5. **无 `#delay`**：综合 RTL 禁止延时；testbench 可用。
6. **无 `initial` 初值**：综合 RTL 禁止；BRAM 初始化用 `$readmemh` 且需单独评审。
7. **命名**：寄存输出加 `_q` 后缀；组合信号不加；低有效加 `_n`。
8. **注释**：每个 `always` 块说明“状态/数据流/为什么这样寄存”；禁止无意义注释。

## 四、接口约束

### 4.1 握手

- 统一使用 `valid/ready` 或 `start/busy/done`；
- `start` 在 `busy=1` 时忽略；`done` 单周期脉冲或电平保持必须在契约中写清；
- 输出数据在 `done` 有效时稳定；`done` 后至少保持 1 周期。

### 4.2 延迟与吞吐

- 每个模块契约必须写明：最小延迟、最大延迟、吞吐（每 N 周期一个结果）；
- 多路并行模块必须给出 `LANES` 参数与资源/周期公式；
- 不允许“延迟取决于秘密数据”而不标注。

### 4.3 AXI4-Lite / BRAM

- 寄存器映射见 `docs/contracts/axi_mmio_v0.md`；
- V0 数据面用 BRAM 映射；V1 再上 DMA；
- `busy=1` 时禁止写数据区；读数据区必须在 `done=1` 后。

## 五、仿真约束

### 5.1 C/C++ 软件仿真（黄金模型）

- 语言：C11；编译：GCC/Clang，`-O2 -Wall -Wextra -Werror`；
- 禁止未定义行为（越界、未初始化、溢出有符号）；
- 每个黄金程序必须支持 `--selftest`，输出 `PASS: N/N` 或 `FAIL: ...`；
- 随机测试必须固定种子，并在日志里打印种子；
- 与官方参考实现对拍时，逐字节比较，不能只比“共享密钥相等”。

### 5.2 Vivado xsim（RTL 仿真）

- 入口：`sim/scripts/run_xsim.tcl`，参数为 testbench top；
- testbench 必须自检，统一输出 `PASS: N/N checks` / `FAIL: ...`；
- 每个 tb 至少覆盖：复位、边界、随机、错误注入（如适用）；
- 波形只在需要时 dump；`.wdb/.vcd` 不入库；
- 日志重定向到 `data/logs/`，并在协作纪录中链接。

### 5.3 Icarus Verilog（可选）

- 仅用于快速 lint / 语法检查；
- **不得**用 iverilog 的结果替代 xsim 作为最终验证依据。

## 六、验证闸门

| 闸门 | 内容 | 通过标准 |
|:---|:---|:---|
| G0 | C/C++ 黄金自检 | `PASS: N/N` |
| G1 | 稀疏乘法 vs 黄金 | 逐 bit 一致，随机 ≥1000 组 |
| G2 | dense 基线 vs 稀疏 | 同一输入结果一致 |
| G3 | RM FHT vs 参考 | 逐块一致 |
| G4 | KeyGen/Encaps KAT | 逐字节一致 |
| G5 | Decaps KAT + 负向 | 逐字节一致；隐式拒绝正确 |
| G6 | 系统仿真 | 完整 RTL KAT 100/100；0 mismatch |
| G7 | FPGA PPA | 资源/时序/周期数入档 |
| G8 | ASIC 综合（条件） | area/power/fmax 入档；工具/PDK 明确 |
| G9 | 上板（可选） | 板端 = 仿真；延迟/资源入档 |

**任何 G 未过，不得进入下一阶段。**

## 八、原创性与引用

1. 复现官方 HQC 参考实现 / 田静组论文 / 第三方 IP，必须注明来源、版本、许可证。
2. 立项书与报告必须有“贡献边界表”：
   | 内容 | 来源 | 本项目工作 |
   |:---|:---|:---|
3. 开题前查新：至少覆盖 HQC 硬件实现与田静组 SOCC 2023 论文 #15；写清差异。
4. 禁止把“复现 + 换参数 + 换平台”包装成原创。
5. 引用格式统一：作者、题目、会议/期刊、年份、DOI。
