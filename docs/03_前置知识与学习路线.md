# 前置知识与学习路线（面向 HQC KEM 硬件加速）

> 目标：从“只学过数电”成长到“能写可综合 Verilog、看得懂 HQC 硬件论文、会看 PPA”。
> 核心能力模型：**能写 Verilog + 能综合出电路 + 看得懂 HQC 算法 + 会看 PPA**。
> 建议投入：每周 15~20 小时，6 个月为一个周期。
>
> **配套文档**：如果“学过数电但还没写过 Verilog”，先看 [`05_前置知识补全_从数电到Verilog实战.md`](05_前置知识补全_从数电到Verilog实战.md)——它把工程基础、四周动手计划和可复用的旧仓库资产讲得更细。
> **项目主线**：[`08_HQC技术路线.md`](08_HQC技术路线.md)；**分工与指标**：[`10_团队分工与国家级指标.md`](10_团队分工与国家级指标.md)。

## 一、知识地图与优先级

| 模块 | 必须掌握 | 优先级 |
|---|---|---|
| Verilog / FPGA | 可综合代码、xsim、Vivado 综合/时序 | ★★★★★ |
| 数学 | GF(2)、多项式环、循环卷积、线性代数基础 | ★★★★★ |
| 编码理论 | 线性码、Reed-Muller、Reed-Solomon 的直观 | ★★★★★ |
| 密码学 | KEM、FO 变换、HQC 流程、隐式拒绝 | ★★★★☆ |
| 数字 IC | 时序、关键路径、面积/功耗、流水线 | ★★★★☆ |
| 计算机算术 | XOR/AND 阵列、加法树、FHT、位切片 | ★★★★☆ |
| 计算机体系结构 | 存储层次、加速器、软硬协同 | ★★★☆☆ |
| 硬件安全 | 侧信道、故障攻击（进组后再深入） | ★★☆☆☆ |

> 真正的最小闭环：**Verilog + GF(2) 多项式运算 + 稀疏乘法硬件**。其他边做边补。
> **不需要**先啃 NTT / 格密码 / Kyber 模约减——那是另一条技术路线。

## 五、第一个动手项目（强推，进组“投名状”）

**用 C/C++ + Verilog 实现 HQC 的 dense × sparse 准循环乘法，并与黄金模型对拍。**

步骤：

1. 用 C/C++ 写黄金模型：输入稠密多项式 $a$、稀疏位置表 $P$，输出 $\bigoplus_{p\in P}(a \lll p) \bmod (X^n-1)$。
2. 写 testbench：读 `data/vectors/qc_mult_small.hex`，逐 bit 对拍。
3. 实现 RTL：按位置循环移位 + XOR 累加 + 折叠。
4. 用 Vivado xsim 跑 1024 组随机向量，输出 `PASS: N/N checks`。
5. Vivado OOC 综合，记录 LUT / FF / BRAM / DSP / WNS，和 dense 基线对比。

做完后可以这样联系导师：

> “我按 HQC 的固定重量稀疏结构，用 C/C++ 黄金模型 + Verilog RTL 实现了准循环乘法，并用官方 KAT 思路对拍；综合结果显示相比朴素 $O(n^2)$ 有明显周期优势。想在 PQC 硬件加速方向继续深入。”

## 七、避坑提醒

1. **别先啃格密码/NTT/模约减**——HQC 是码密码，技术路线不同；先把 GF(2) 和稀疏乘法搞清。
2. **别只看视频不动手**——Verilog 必须写，HDLBits 比看十门课有用。
3. **别贪多**——先“Verilog + GF(2) 多项式运算 + 稀疏乘法硬件”这三样，其他边做边补。
4. **中文优先**——中国大学 MOOC 的 Verilog / 数电课足够入门，别一上来啃英文教材。
5. **每写一个模块都要有测试平台**，否则后期调试成本极高。
6. **代码与实验数据尽早进 Git**（就是本仓库），养成版本管理习惯。
7. **先完整仿真，后上板**——不要因为没板子就停下；xsim + 综合也能交付完整 KEM。
