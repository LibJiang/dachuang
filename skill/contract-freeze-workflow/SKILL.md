# 契约冻结工作流

一句话规则：**冻结前枚举全部用例，冻结后缺口“只登记、不放宽”；没有冻结契约，不许写代码。**

## 适用范围

- RTL 模块端口、握手、延迟；
- 寄存器映射、AXI/MMIO、BRAM 地址；
- 数据格式（位序、字节序、稀疏位置表、KAT 格式）；
- C/C++ 黄金接口、脚本输入输出；
- 任何跨模块/跨人/跨语言（RTL ↔ C ↔ Python）的接口。

## 流程

### 1. 冻结前：枚举全部用例

- 列出目标域的**全部**用例：所有操作码、所有字段、所有状态、所有位宽、所有参数集；
- 逐项核对预留位宽/枚举/白名单是否装得下；
- 发现缺口 → 写“问题清单 + 选项”，实现前拍板；
- **不允许**“先写代码，冻结以后再说”。

### 2. 写契约

使用 `docs/contracts/TEMPLATE.md`，至少写清：

- 模块/接口名、版本、负责人、状态；
- 端口/寄存器/字段、位宽、方向、时钟/复位；
- 数据格式（位序、字节序、稀疏位置表、KAT）；
- 时序：最小/最大延迟、吞吐、握手（`valid/ready` 或 `start/busy/done`）；
- 错误行为（越界、非法参数、超时）；
- 验证方法（tb、向量、KAT、对拍）；
- 未决问题（冻结前必须清零，或明确“不实现”）。

### 3. 评审与冻结

- 至少 1 名非作者评审：检查用例空间、位宽、握手、错误行为；
- 评审通过 → 状态改为 `冻结`，在 `report/llm_log/` 写一条“契约冻结”纪录；
- 冻结后任何改动 → 新版本 `_v1.md`，旧版本保留，不得原地改语义。

### 4. 负例先行

- 修复/实现前，先写一个**会 FAIL** 的测试，对旧代码跑出 FAIL，留证“缺口真实存在”；
- 再修复，让正负例矩阵 PASS；
- 正例：合法边界；负例：越界、反向、未知枚举、重复、非法位宽。

### 5. 三处同步

接口/格式变更必须同时更新：

1. RTL；
2. testbench / 系统仿真；
3. C/C++ 黄金 / KAT / 脚本；
4. 对应契约文档。

只改一处，会出现“仿真侥幸 PASS、上板/联调失败”。

### 6. 演化纪律

- 实现缺口被发现时：只登记，不放宽冻结条款；
- 新增字段/位宽：版本评审 + 决策记录 + 三处同步；
- 引用“已冻结”章节前，先 `git show` 确认存在，不凭记忆。

## 失效条件

- 探索性原型（契约本身未定）：先实验，但冻结前必须走第 1 步；
- 单人单文件内部接口（无跨端对齐）：可简化，但仍要写清端口/位宽；
- 第三方协议只实现不定义：本流程管“客户端校验与登记”，管不了对方违约。
