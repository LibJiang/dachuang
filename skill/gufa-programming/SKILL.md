# 古法编程（契约先行 + 小步交付 + 逐步出题）

一句话规则：**没有冻结契约，不许写代码；每步 ≤100 行，出题过关再走下一步。**

本仓库的目标是国家级大创，代码线包括：

- Verilog RTL / testbench；
- C/C++ 黄金、KAT、脚本；
- Python / Tcl / shell / PowerShell 工具；
- 任何会进入交付物的代码。

以上全部适用，不限于 RTL。

## 与 understand-gate / contract-freeze-workflow 的分工

| 技能 | 作用 |
|:---|:---|
| **contract-freeze-workflow** | 开发**前**：接口/寄存器/数据格式先冻结 |
| **古法编程** | 开发**中**：小步交付、逐步出题、防止一次性倾倒 |
| **understand-gate** | commit **前**：逐段讲解 + 3 题，用户确认后才提交 |

## 流程

### 第 0 步：契约检查（硬性）

- 本次要改的模块/接口，是否已有**冻结**的契约？
- 没有 → **不许写代码**；先按 `skill/contract-freeze-workflow/SKILL.md` 起草、评审、冻结。
- 契约位置：`docs/contracts/<模块>_v0.md`；模板：`docs/contracts/TEMPLATE.md`。
- 契约必须写清：端口、位宽、数据格式、时序/延迟、握手、错误行为、验证方法。

### 第 1 步：拆步（写代码之前）

- 先给**步骤清单**：每步交付物、涉及文件、预估行数、验证方式。
- 单步粒度：一个模块 / 一个 always 块 / 一个函数 / 一个脚本功能点。
- 预估超过 **100 行**（不含注释空行）→ 必须再拆。
- 清单经用户确认后才开工；中途加步/拆步先说明。
- 用 todo 清单维护步骤状态。

### 第 2 步：单步实现

- 只做当前这一步，不顺手改后面的东西。
- 新增/修改 ≤100 行（默认阈值；用户可指定更小）。
- 中间讨论可以展开，但**代码只给当前步**。

### 第 3 步：本步自检

- 能跑就跑：编译/仿真/lint 的命令 + 原始结果，禁止只报“应该没问题”。
- RTL：xsim 自检 tb，输出 `PASS: N/N checks`。
- C/C++：黄金自检或 KAT，输出 `PASS: N/N`。
- 本步无法独立验证 → 明确说明原因，不许含糊。

### 第 4 步：讲解 + 出题（硬性卡点）

- **讲解**：本步设计意图、关键信号/变量为什么存在、与契约的对应章节。
- **出题**：2–3 道“如果改成 XX 会怎样”，从零水平出发。
- **等用户回答**；不通过 → 补讲 + 补 1 道新题再测，直到通过。
- 禁止：替用户作答、放水降难度、没等回答就继续写。

### 第 5 步：下一步

- 用户确认理解后才进入下一步。
- 用户明确说“这步我懂，跳过出题”→ 可跳过该步题目（豁免要在收尾留痕）。

### 第 6 步：收尾

- 全部步骤完成：跑全量回归，按 `skill/understand-gate/SKILL.md` 走 commit 前流程。
- 各步题目/答案/判定归档进 `report/llm_log/`。

## 拆步示例

| 任务 | 推荐拆法 |
|:---|:---|
| 新 RTL 模块 | 接口 + 空实现 → 主逻辑 → 边界/复位分支 |
| 新 testbench | 骨架 + 激励 → 判据 + 自检打印 |
| 新 C/C++ 黄金 | 数据结构 → 参考算法 → 对拍脚本 |
| 新脚本 | 参数解析 → 主流程 → 错误处理 |

## 失效条件（豁免）

- 纯文档 / `.gitignore` / `llm_log` / `data` 记录类改动；
- 一行修复（typo、改常量）且用户认可；
- 用户显式说“快速模式 / 别出题 / 一次写完”；
- 探索性 spike（注定要扔的代码）——转正式实现时补走流程。
