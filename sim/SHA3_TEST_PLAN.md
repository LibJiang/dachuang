## 1. 验证边界

目标 DUT 为 `sha3_shared`，未来 tb 为 `sim/tb_sha3.v`，只使用公开端口驱动与比对。
覆盖 SHAKE256、SHA3-256、SHA3-512 的结果、流控、复位、模式切换和错误处理。
系统级三阶段仲裁、sampler 联调、完整 KEM KAT、面积和板端验收另行完成。
本单元测试通过不能证明恒定时间或抗侧信道能力。

| mode | 算法 | rate（B） | padding 后缀 | 合法 out_len（B） |
|:---|:---|:---|:---|:---|
| 0 | SHAKE256 | 136 | `0x1F` | 1–65535；0 表示连续 XOF |
| 1 | SHA3-256 | 136 | `0x06` | 32 |
| 2 | SHA3-512 | 72 | `0x06` | 64 |

合法 phase 为 0/1/2；phase 只作为调用标签，相同输入/模式的输出应一致。

## 3. 功能测试矩阵

下表长度单位均为字节；每种模式使用自己的 rate R。
输入图案至少含全 0、全 FF、递增字节和固定种子的伪随机消息。

| ID | 用例 | 必查判据 |
|:---|:---|:---|
| F01 | 三种模式的空输入 | 无输入握手即可完成；结果等于黄金 |
| F02 | 输入 1/7/8/9 B | 字节顺序、单字边界及尾部处理正确 |
| F03 | 输入 R−1/R/R+1 B | padding 和整 rate 时额外填充正确 |
| F04 | 输入 2R−1/2R/2R+1 B | 多块吸收正确、无跨块状态丢失 |
| F05 | 输入 65535 B | 16-bit 长度上界，无溢出或截断 |
| F06 | SHAKE 输出 1/7/8/9/135/136/137/272/273/65535 B | squeeze 跨字/跨 rate 正确 |
| F07 | 相同短尾输入两次，改变无效高字节 | 输出完全相同，无效字节未参与吸收 |
| F08 | phase=0/1/2 重复同一合法事务 | 输出一致；无停顿调用周期一致（性能观察） |
| F09 | 三种 mode 连续交替调用，不逐例复位 | 结果各自正确，不残留上一上下文 |
| F10 | 公开合成 G/H/I/J 及带域分隔的 XOF 消息 | 上游拼接完整消息，含域字节，与 symmetric.c 黄金一致 |
| F11 | 同一 XOF 上下文分段消费 3/5/136/1 B | 所消费字节拼接等于黄金前缀，不重启流 |

F11 的分段指消费者累计字节数；当前 DUT 仍按 64-bit beat 交付。
3/5 B 等非整字分段需要消费者字节缓存，不得假设 SHA3 核能撤销已握手的部分字节。
真实 y→x、r2→e→r1 的共享字节缓存行为留给 sampler/系统级测试。

## 4. 协议、复位和负例矩阵

| ID | 用例 | 判据或评审依赖 |
|:---|:---|:---|
| P01 | 无停顿输入/输出 | 输入与输出只在 valid && ready 时计数；结果与长度匹配 |
| P02 | 输入间歇 valid、输出交替/连续拉低 ready | 不丢字、不重复；最终结果不受停顿影响 |
| P03 | 输出最后一拍持续背压 | out_data/out_keep/out_last/out_valid 保持；done 不提前 |
| P04 | busy 中再次 start，携带不同 mode/length | 当前事务不被重启或污染；合法事务仍正常完成 |
| P05 | 空闲、吸收、计算、输出和背压期间复位 | busy/done/error 清零、输出无效；新事务不残留旧结果 |
| P06 | mode=3；phase=3 | error 置位；后续恢复及无效输出规则待契约确认 |
| P07 | SHA3-256 out_len=0/31/33；SHA3-512=0/63/65 | 拒绝非法长度，不能解释成连续 SHAKE |
| P08 | 非 SHAKE 模式使用 xof_stop | 按契约报错；生效时点与恢复规则待确认 |
| P09 | error 后空闲多拍，再合法 start | error 保持到合法 start；后续结果正确 |
| P10 | XOF out_len=0，输出至少 273 B | 与黄金前缀一致；未 stop 前不自然 done |
| P11 | XOF stop 遇到背压、最后消费同拍或吸收未完成 | 接受优先级/尾拍处置待评审，先列 BLOCKED |
| P12 | 固定种子随机停顿回归，每种 mode ≥1000 例 | 字节/握手/结束自检全部通过；打印种子与用例 ID |

驱动器必须在 `in_valid && !in_ready` 时保持 in_valid/in_data，不把非法驱动当 DUT 错误。
复位和非法请求的状态判定使用四态比较，X/Z 必须失败；正常背压本身不算超时错误。
事务中修改配置是否应被忽略、有限 SHAKE 使用 stop 的行为，先进入评审，不擅自定为正/负例。

## 5. 自检结构和通过标准

后续 tb 包含 driver、字节级 scoreboard、握手监视器、复位/错误检查及 watchdog。
使用与 DUT 采样沿错开的激励，避免 TB 与时序逻辑竞态；采样点统一约定。

- 仅在输出握手时逐字节推进 scoreboard，按 out_keep 检查有效低字节。
- 有限输出恰好 `ceil(out_len/8)` 次握手；满字 keep=FF，尾字 keep 的低剩余位为 1。
- 最后一拍且仅最后一拍 out_last=1；有限流 done 与尾拍接受一致，单周期有效。
- 不比较无效高字节的具体数值；但背压时整个输出总线须稳定。
- 每例检查精确字节数、无额外输出、正常完成后 busy 退出；完成后的观察窗口待延迟契约确定。
- watchdog 单独限制测试等待；它不定义硬件的安全超时，也不证明拒绝采样有固定上界。
- 无停顿 cycles、输入等待周期、输出背压周期分别统计；未定延迟上界前不宣称固定周期通过。
- 正常打印 `PASS: N/N checks` 和测试例数；错误打印 case_id、错误类型与计数。
- 每例任何数据不符、协议错误、超时都必须使批处理返回非 0；所有启用用例通过才 PASS。
- BLOCKED/SKIP 单独计数；关键条目未覆盖时总结果只能 PARTIAL，不得用 0 个检查输出 PASS。

负向验证先故意篡改一份公开预期答案的一个字节：必须被 scoreboard 检出并返回失败。
再恢复正确黄金运行正例矩阵，排除 tb 永远打印 PASS 的假通过。
